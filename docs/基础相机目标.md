# 基础相机目标

建立：2026-11-15（Asia/Tokyo），用户要求持续推进至完成。

## 首期范围

在小米 13 主线 Linux 上使用 OV13B10 超广角完成稳定取景、拍照保存与回看、
正常退出重开。优先复用已有 libcamera 和相机应用，修复阻塞流程的 CAMSS/MM0
生命周期问题，提供可复现构建、安装入口及实机验证记录。

首期不要求主摄/前摄/长焦、录像、AF/OIS 或原厂徕卡算法。这些保留在
[完整功能矩阵](相机功能完成矩阵.md)，不作为基础目标的完成条件。

## 验收条件

| 项目 | 完成条件 | 当前状态 |
| --- | --- | --- |
| 底层启停 | 同进程启停和应用退出重开各连续 20 次；无 MM0/RPMh 超时、持续 D 状态、内核告警或残留采集进程 | 未完成；cam11reset 单次 RGB 停机握手成功，但同进程第二轮仍阻塞互连 |
| 取景 | 普通用户从桌面打开，连续取景 10 分钟；目标至少 1052×780、平均 15 fps，画面持续更新且方向正确 | 未完成；已有实验 RGB 出图 |
| 拍照 | 至少 2104×1560 JPEG，连续保存 30 张；文件唯一、完整可解码，拍照后取景继续，失败有明确提示 | 未完成 |
| 回看 | 应用内或系统图片查看器打开已保存照片；退出相机后文件仍可访问 | 未完成 |
| 基础画面 | 日常光照下可辨认场景，无冻结、撕裂或持续短横线；记录曝光/颜色和低光局限，保留经检查的样张 | 未完成；短横线问题尚待复查 |
| 错误处理 | 相机占用、保存失败和正常关闭可退出并恢复操作，不留下半写文件或永久等待 | 未完成 |
| 系统集成 | 桌面入口、普通用户权限、可复现依赖与源码/补丁/配置/包校验；正常重启后重新验证取景、拍照和回看 | 未完成 |
| 保留通过版本 | 新版通过实机验收后保留运行和默认启动，旧版仅作为故障恢复入口 | 已确立规则，待新候选验收 |

帧率、时长和循环数记录实际观测，不能只凭命令参数认定通过。测试覆盖实际
传感器和采集链路，独立 EGL 测试或主机 KUnit 不替代实机。程序超时不保证能
终止内核 D 状态任务，故障后停止追加采集，保留现场并按已验证入口恢复。

## 开发基准与步骤

1. 从最新主机验证通过的 `cpas-order` 源码提交
   `cd5ca4eecfdf2a119f1e38f1dd067f167ac84b72` 向前开发，完整 cam12order 包待安装。手机运行/默认 cam11reset，
   正常启动通过；路径复位后单次 RGB 60 帧的 CPAS 停机握手成功，但同进程第二轮
   仍阻塞互连、影响 UFS/CPU/GPU。实时跟踪已定位再次启动 MM0 请求发生在 CPAS
   start 之前并超时；本次正常重启未完成，需先恢复设备。主机 38 项内核测试
   不能替代实机生命周期验收，未回退。
2. 实现并验证全局 CPAS 时钟/供电持有、启动及停机握手和失败路径，先做有意义的
   内核故障测试，再用新候选执行实机启停。记录 ICC/RPMh 错误传递和回滚边界。
3. 复用已通过验证的 libcamera 首帧、GPU 图像回收及 context 清理补丁，接通基础
   相机应用的取景、JPEG 保存及回看，补齐相应错误处理。
4. 完成上表实机矩阵与重启复验，记录构建版本、样张检查、日志摘要和剩余限制；
   每完成一项更新状态，全部达到后才标记基础目标完成。

按用户要求，成功验证后不例行退回 deb9/deb8。开发基准推进不代表完整四摄或
正式发布晋级。保留一个已验证旧内核，仅在明确故障或用户要求时回退并记录原因。
