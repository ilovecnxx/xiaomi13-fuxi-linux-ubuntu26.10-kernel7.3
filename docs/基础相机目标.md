## 首期范围

在小米 13 主线 Linux 上使用 **IMX800 后置主摄**完成稳定取景、拍照保存与回看、
正常退出重开。优先复用已有 libcamera 和相机应用，修复阻塞流程的 CAMSS/MM0
生命周期问题，补齐主摄 C-PHY 接收链路、传感器驱动和设备树，提供可复现构建、
安装入口及实机验证记录。主摄已读到 ID，但尚未出图，不能把超广角成果算作主摄通过。

超广角、前摄、长焦、镜头切换、录像和原厂徕卡算法延期，保留在
[完整功能矩阵](相机功能完成矩阵.md)。先完成主摄单模式基础流程；AF/OIS 尚未
实现，需要记录固定焦点下的实际清晰范围。若无法获得可辨认的基础画面，则继续
解决主摄对焦，不能以 AF/OIS 延期为由跳过画面验收。

## 开发基准与步骤

1. 从最新主机验证通过的 `cphy-stream` 源码提交
   `e2fbde80b361479aec65e7e254910f6b18d41dbf` 向前开发：保留共享修复，已贯通 SM8550
   C-PHY 端点、频率/校准 settle 配对和 PHY 2.1.2 启停，补启动失败清理；125 项内核测试、
   ARM64 W=1 和设备树 schema 通过。V4L2 停流错误仍被记录后返回成功，不能据此证明硬件空闲。
   实际主摄 PLL、trio 接线、传感器驱动/本机设备树及实机验证仍待完成。
   手机运行/默认 cam12order，
   正常启动及单次 RGB 60 帧通过，停机资源归零；同进程第二轮在 CPAS start 成功后
   仍发生 MM0 超时并影响 UFS/CPU/GPU。故障后已恢复新启动，Linux/SSH 可用、Phosh
   active、失败服务零、无 D 状态线程，未再采集。主机测试与超广角单次出图
   不能替代相机生命周期验收；保留当前候选和 deb9 恢复入口，没有例行回退。
2. 按[主摄接通计划](主摄接通计划-20261115.md)补齐端点总线类型传递、SM8550
   C-PHY/trio、CSID 接收配置及 IMX800 驱动，先打通一个本机核实的非 HDR 模式。
   保留共享 CPAS/ICC 修复并验证错误传递、失败回滚及启停，避免扩展其他镜头功能。
3. 复用已通过验证的 libcamera 首帧、GPU 图像回收及 context 清理补丁，接通主摄
   相机应用的取景、JPEG 保存及回看，补齐相应错误处理。
4. 完成上表实机矩阵与重启复验，记录构建版本、样张检查、日志摘要和剩余限制；
   每完成一项更新状态，全部达到后才标记基础目标完成。

按用户要求，成功验证后不例行退回 deb9/deb8。开发基准推进不代表完整四摄或
正式发布晋级。保留一个已验证旧内核，仅在明确故障或用户要求时回退并记录原因。
