# 内核维护与独立升级

本文是当前操作入口。历史 shim、ABL 直启及 BLS 调研记录不再作为日常操作步骤。

## 启动与职责

```text
ABL -> recovery_b: U-Boot uboot7
    -> /boot/extlinux/extlinux.conf
    -> /boot/fuxi/<版本>/{Image,板级DTB,initrd.img,cmdline}
    -> initramfs-tools -> Ubuntu 根文件系统
```

日常内核升级只修改 Linux 分区，不刷 recovery_b，也不改 Android/固件分区。
U-Boot 仍保留固定引导层；`fuxi-device` 提供启动管理工具与钩子；内核包提供
Image、DTB 和配置；initramfs-tools 生成独立 initrd。不要手改自动生成的 extlinux 文件。

## 构建

源码、补丁分类和配置策略见 [`kernel/README.md`](../kernel/README.md)。

```bash
python3 scripts/fuxi-kernel-source.py prepare
scripts/fuxi-build-deb.sh <唯一名字>
```

无网络时给 prepare 传 `--archive <压缩包>`，校验值必须与清单一致。
构建产物在 `work/kbuild/<名字>/`；先在该目录运行 `sha256sum -c SHA256SUMS`。
实验树必须显式指定 `FUXI_KTREE` 和 `FUXI_KOUT`，不得覆盖稳定源码树。

## 安装与验收

将经校验的 deb 传到手机 `/tmp/`，在手机 Linux 上执行：

```bash
dpkg -i /tmp/linux-image-<版本>_arm64.deb
fuxi-kernel-install list
fuxi-bootcount show
```

安装依次生成 initrd、创建启动条目、把当前已确认内核设为回退，并设置新内核默认。
重启前检查默认/回退条目的 Image、DTB、initrd 和 `SHA256SUMS` 都完整，核对
`/etc/kernel/cmdline` 中的根文件系统 UUID。已有版本不能用同名新构建覆盖。

```bash
systemctl reboot --reboot-argument=recovery
```

重新连上后核对 `uname -r`、`fuxi-kernel-install list`、`fuxi-bootcount show`、
`systemctl --failed`，再运行主机的 `scripts/fuxi-health.sh`。
`pending=0 tries=0 once=0` 表示本次启动已确认；成功编译不能代替实机验收。

## 回退和清理

```bash
fuxi-kernel-install set-default <已验证旧版本>
systemctl reboot --reboot-argument=recovery
```

连续两次未确认启动后，U-Boot 自动使用 fallback.conf；该流程已经用真实损坏
initrd 验证过。它保护启动故障，不保证识别所有外设功能回归，后者仍需人工验收。

只清理不在运行、不是默认、也不是回退的版本。先用 `fuxi-kernel-install list`
核对，再通过 `dpkg --purge <旧内核包名>` 删除包。无包归属的旧实验条目用
`fuxi-kernel-install remove <条目>`；常规维护不使用 `--force`。
默认至少保留当前内核与一个已验证回退版本。

shim7 镜像仅作历史应急回滚，相关脚本在 `scripts/legacy/`。条目保留 initrd
硬链接兼容它，但兼容修复后的 shim7 启动尚未上机验证，不能视为已验收回退路径。
当前已验证的日常回退是 U-Boot 的多内核回退。
