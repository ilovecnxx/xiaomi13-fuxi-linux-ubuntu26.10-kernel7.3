# 快充开源实现调研（2026-11-07）

## 结论

有可参考的开源代码，而且不只有标准 USB PD/PPS 协议栈：Armbian 的 Xiaomi sheng BSP
包含小米 MiPPS 认证脚本及配套主线内核驱动。它是当前 fuxi 移植最值得核对的实现。
尚未把它移植到本机，也未据此验证高压快充；5 V / 约 6.9 W 仍是本机的实际状态。

本次通过公开 Git 仓库与 raw 源码在线读取，核对的版本如下：

| 来源 | 核对版本 | 代码与用途 |
|---|---|---|
| Armbian build | `c95374efd50807424c906e885d3b2c0452c27ba4` | GPL-2.0-only 的 Python MiPPS 认证程序、systemd 服务、udev 触发规则 |
| ianchb/sm8550-mainline | `sheng-7.2.2` / `dd8bbe0acff33bb739f1f6ed3091946e052cd39b` | GPL-2.0-only 的 qcom_battmgr 小米扩展，支持摘要与 UVDM 消息 |
| MiCode/Xiaomi_Kernel_OpenSource | `fuxi-t-oss` 分支，在线读取 | 小米官方 fuxi 的 GPL-2.0-only 充电驱动；用于核对旧版消息结构，不能直接套用属性编号 |
| Seyud/FreePPS | `5dedf91f5b3672ef62818eeef435813fb11e8bd9` | GPLv3，Android 模块，通过现有厂商 sysfs 写认证标志，不是完整主线 PD 驱动 |

## 最相关：Armbian sheng

Armbian 的 `config/sources/families/sm8550-sheng.conf` 指向 ianchb 的内核，
因此用户态与内核接口有明确的配套关系。sheng 为小米平板 6S Pro，使用 SM8550，
但电池拓扑和充电硬件不能视为与 fuxi 相同。

Python 程序实际包含：

- 对电量计发送随机挑战，通过 `verify_digest` 获取摘要，用 HMAC-SHA256 校验，按校验结果写 `authentic`。
- 通过 `request_vdm_cmd` 发送充电器查询、会话种子和随机挑战，核对充电器响应与 adapter ID。
- 发送认证结果、反向认证及补偿相关命令，按实际结果写 `pd_verifed`。
- Type-C 数据角色处理，以及 USB 插入后的 udev/systemd 调度。

它不是单纯固定写 `pd_verifed=1`。不过脚本包含 sheng 双电量计验证、机型相关的密钥候选与专有属性，
这些均需在 fuxi 上核实。不能把脚本执行成功或认证标志变为 1 当作快充通过。

## fuxi 移植差异

本机 deb5 现有 `diag` 能读取部分属性，`xm_set` 只能发送一个 u32 值。
它没有上述摘要、UVDM 多字消息的用户接口，直接运行认证脚本会缺节点。
配套 sheng 驱动中有 32 字节摘要消息和 4 个 u32 的 UVDM 消息，不能用普通单值 SET 替代。

小米官方旧版 fuxi 源码中，`XM_PROP_VERIFY_PROCESS` 为 8、`XM_PROP_PD_VERIFED` 为 20；
此前通过官方 309 模块核对的运行固件值分别为 12、24（见提交 `60b3b80` 的 TASKS）。
当前 sheng 扩展采用 12、24，与这部分运行固件编号吻合，但其他新增属性仍须逐项核对。

本机当前 `AUTHENTIC=0`、`PD_VERIFED=0`、`FASTCHGMODE=0`；
这些是查认证路径的线索，尚未证明其中哪一项是停留在 5 V 的必要条件。
公开主机端代码也不意味着 ADSP 内部充电策略及全部固件已开源。

具体移植顺序：

1. 以本机 309 模块为准核对摘要/UVDM 消息结构、属性编号、返回长度和错误码；核实单/双电量计。
2. 在现有 qcom_battmgr 上引入所需消息与受限接口，保留锁和响应匹配，避免未经匹配的 0x50 消息完成其他请求。
3. 适配认证程序的电池配置与插拔生命周期，保留实际摘要验证结果。
4. 编译与部署后，先验电池认证，再验充电器认证，最后实测 VBUS、电池净入电与温升。
   只有高压/高功率持续采样通过才记为快充解决。

## 其他来源

- [小米官方 fuxi 驱动](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/fuxi-t-oss/drivers/power/supply/qti_battery_charger.c)：消息结构和原厂 sysfs 处理参考；不是当前 309 固件的精确头文件。
- [FreePPS 说明](https://github.com/Seyud/FreePPS/blob/5dedf91f5b3672ef62818eeef435813fb11e8bd9/docs/README.md)：面向 Android 公版 PPS；其实现向 `pd_verifed` / `usbpd_verifed` 写布尔值，依赖原厂节点，不能直接当作 Ubuntu 主线驱动安装。
- [Linux TCPM](https://github.com/torvalds/linux/blob/master/drivers/usb/typec/tcpm/tcpm.c)：标准 PD/PPS 协议栈；本机走 PMIC GLINK/UCSI 和 ADSP，不能仅启用 TCPM 就接管这条固件链路。

本次调研没有向设备写入认证标志、修改充电电流上限、重启或刷写分区。
