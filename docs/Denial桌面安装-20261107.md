## 手机侧改动

1. `/etc/denial/session.conf` 末尾追加手机形态（原文件备份为 `session.conf.orig-20261107`）：

   ```
   # Xiaomi 13 fuxi: phone shell (mobile) default
   DENIAL_SHELL_PROFILE=mobile
   ```

   （PC 包默认 desktop；`denial-session --check` 现在报 `shell profile mobile`。
   `denial.service` 里也设置了同名环境变量，双重保险。）

2. 新增会话 unit `/etc/systemd/system/denial.service`（源文件在
   `work/rootfs-overlay/etc/systemd/system/denial.service`）。手机没有 display manager
   （没有 gdm/sddm，图形会话是系统级 `phosh.service` 直接占 tty7），所以照
   `phosh.service` 的样子写一个系统 unit：

   - `Conflicts=phosh.service plasmamobile.service getty@tty7.service`，同一时刻只有
     一个合成器拿 DRM master；
   - `User=1000`、`PAMName=login`、`TTYPath=/dev/tty7`、`LIBSEAT_BACKEND=logind`、
     `UtmpIdentifier=tty7`，和 Phosh 一样得到 logind 的 seat/DRM；
   - `ExecStartPre` 先拉起用户 bus（`systemctl --user --machine=fuxi@.host start
     dbus.socket`）并 `chvt 7`；
   - `ExecStart=/usr/bin/dbus-run-session -- /usr/bin/denial-session`；
   - **不要**设 `WAYLAND_DISPLAY`（见“坑”第 1 条）；
   - `Restart=on-failure`，`systemctl is-enabled` = disabled，开机不自动进 Denial。

3. `/usr/local/bin/fuxi-session` 增加 `denial` 分支（Phosh / Plasma 切换时也会停
   Denial 并清掉残留 `deniald`）。源文件在 `work/rootfs-overlay/usr/local/bin/fuxi-session`。

## 切换与回退

```sh
scripts/fuxi-ssh.sh 'fuxi-session denial'   # Phosh → Denial（实测 17 s）
scripts/fuxi-ssh.sh 'fuxi-session phosh'    # Denial → Phosh
```

开机默认会话改成 Denial（2026-11-07 04:03，已执行）：

```sh
systemctl disable phosh.service     # 去掉 graphical.target 里的 Phosh
systemctl enable denial.service     # 换成 Denial（graphical.target.wants/denial.service）
```

回退成开机进 Phosh：

```sh
systemctl disable denial.service
systemctl enable phosh.service
```

如果下次开机 Denial 起不来（黑屏）：SSH 还通（网络是系统服务），执行上面的回退三条，
再 `systemctl start phosh.service`。

- 切换会断开当前图形会话（手机屏幕会黑一下再出现新桌面），SSH 不受影响。
- 如果 Denial 起不来导致黑屏：SSH 上执行 `fuxi-session phosh` 即可恢复
  （2026-11-07 实测过一次失败回滚：`denial-session` 拒绝启动后 Phosh 正常拉起）。
- 会话顺序：先 `systemctl stop phosh.service`（phoc 偶尔对 SIGTERM 不退出，systemd
  90 s 超时后 SIGKILL，这一次切换因此变慢），再 `systemctl start denial.service`。

## 坑（已踩过）

1. **`WAYLAND_DISPLAY` 不能传给 `denial-session`**：它用这个变量判断“已有合成器在跑”，
   直接报 `a Wayland compositor is already active; log out before starting Denial` 并退出
   （第一次切换就这么失败的）。unit 里用 `UnsetEnvironment=WAYLAND_DISPLAY`。
2. 手机没有 display manager，`/usr/share/wayland-sessions/denial.desktop` 不会被用到；
   必须自己写 `denial.service`（或改用 SDDM/greetd，会牵动 Phosh 启动方式，没做）。
3. Phosh 残留的 `wayland-0` socket 还在（phoc 被 SIGKILL），Denial 只好用 `wayland-1`
   （Xwayland 跟着用 `:1`）。功能正常，只是编号变了；grim 截图要用 `WAYLAND_DISPLAY=wayland-1`。
4. Denial 会话退出（注销/断电菜单里的注销）后没有自动回退会话，tty7 会空着。
   需要 SSH 上 `fuxi-session phosh` 或重启。要不要做“退出 Denial 自动拉 Phosh”待定
   （注销、切 Plasma、关机三种情况要区分，不能无脑拉）。
5. 手机里 2026-10-31 源码构建的缓存（`/home/fuxi/denial-cache` 15 GB、`denial-src` 77 MB）
   已于 2026-11-07 04:03 删除（只留 `denial-logs` 180 KB）：根分区 30 GB→16 GB 已用，剩 82 GB。

## DeepSeek App（DSH Web）在 Denial 下打不开（2026-11-07 修复）

- 症状：Denial 桌面点“DeepSeek”图标，窗口不出来或闪一下；`journalctl --user -u dsh-app-window`
  里 Chromium 每 2 s 重启一次（restart counter 到 58）：
  `Failed to connect to Wayland display: 没有那个文件或目录 (2)` →
  `Failed to initialize Wayland platform`。
- 根因：`~/.config/systemd/user/dsh-app-window.service` 和启动脚本**写死
  `WAYLAND_DISPLAY=wayland-0`**。Phosh 的 socket 是 `wayland-0`，Denial 的合成器 socket 是
  `wayland-1`（Phosh 被 SIGKILL 后残留的 `wayland-0` 是死 socket）。
- 修复（`work/dsh-phone/install-remote.sh` 同步改，重新部署即可带上）：
  - `dsh-app-window-run` / `dsh-web-open` 加 `wayland_ok` / `find_wayland_display`：
    遍历 `/run/user/1000/wayland-*`，只认 `ss -xl` 里真有监听者的 socket（忽略 `.lock`
    和死 socket），找不到才退回 `wayland-0`；
  - `dsh-app-window.service` 删掉写死的 `Environment=WAYLAND_DISPLAY=wayland-0`。
- 验证（2026-11-07 04:21，内核 `7.4.0-rc1-fuxi-deb2`）：清掉旧 Chromium 实例后，
  **不设 `WAYLAND_DISPLAY`** 直接跑 `/usr/local/bin/dsh-web-open` → `dsh-web.service` 起来、
  `dsh-app-window.service` active、Chromium 连上 `wayland-1`；
  DevTools 标题 `这个系统有bug吗 — DeepSeek Harness`；截图 `work/denial-arm64/dsh-fixed3.png`。
  首次加载约 40 s（冷启动解析 JS），之后正常；日志里的 Vulkan 报错不影响
  （`--ozone-platform=wayland` 不兼容 Vulkan，走 ANGLE/GL 渲染）。
- 顺带修 `scripts/fuxi-shot.sh`：不再写死 `wayland-0`，按监听中的 socket 选；截图尺寸也不再
  假设 2688×6000（Denial 直接给 1080×2399，原来的 crop 会失败）。
