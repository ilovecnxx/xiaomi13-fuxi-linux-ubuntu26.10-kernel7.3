## 本机 PHY 来源核对

对本地原厂 DTB 使用 `fdtget` 读取属性，并与既有反编译文件交叉检查：

| 对象 | 核实结果 |
| --- | --- |
| `/soc/qcom,cci0@ac15000/qcom,cam-sensor0` | `csiphy-sd-index = 2`，`clock-rates = 19200000`，CCI master 1 |
| `/soc/qcom,csiphy2@ace8000` | compatible 为 `qcom,csiphy-v2.1.2` / `qcom,csiphy`，寄存器范围 `0xace8000 + 0x2000` |
| MiCode 对应版本 | `cam_csiphy_soc.c` 将该 compatible 映射到 `ctrl_reg_2_1_2`，启用 divisor-32 分支 |

本地 DTB：`work/device-info/fuxi-live.dtb`，SHA256
`616602d1b5300214fa51a3a9c2f248c57265f6f7aca2d9ef90d54540275c32e1`。
仅记录所需硬件属性，不提交原始 DTB。

公开驱动来源固定为 MiCode `camera-kernel` 提交
`6c6099a85cb3154fc8a744c17b6b9f5fd361dea8`：

- `drivers/cam_sensor_module/cam_csiphy/include/cam_csiphy_2_1_2_hwreg.h`
  提供独立三相表、common/reset/IRQ 配置、lane-enable 表和随数据率变化的配置表。
- `drivers/cam_sensor_module/cam_csiphy/cam_csiphy_soc.c:280` 选择 2.1.2。
- `drivers/cam_isp/isp_hw_mgr/isp_hw/ife_csid_hw/cam_ife_csid780.h:1220`
  定义 `phy_type_shift = 24`；ver2 RX 路径按 lane_type 写入该位，C-PHY 类型值为 1。

因此 PHY 版本及主摄连接的 PHY 实例已有本机依据；trio 实际接线、模块选择、
符号率和 settle 编码仍待核实。不能把已知 PHY 版本等同于完整链路配置。

## 本次代码

隔离配方位于 `kernel/experiments/camera/cphy-rx/`：

1. 从已解析端点保存总线类型，经 CSIPHY 传给 CSID；连接测试图源时明确重置类型。
2. SM8550 C-PHY 链接检查 1–3 个 trio、编号 0–2、无重复；非法配置在修改接收状态
   之前返回错误，其他 SoC 暂不开放。
3. CSID780 的传感器输入按总线类型设置 RX_CFG0 bit 24，保留 D-PHY 与测试图源路径。
4. 新增实际 link_setup 和寄存器写入的 KUnit 回归，覆盖重映射、非法输入及类型切换。

端点解析入口仍明确拒绝 C-PHY，避免缺少 PHY 编程时启流。这是接收端准备补丁，
不是主摄可用包；未添加传感器模式表、设备树或完整 PHY 支持，不改变标准配方。
