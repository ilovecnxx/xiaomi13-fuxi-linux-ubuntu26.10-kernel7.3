# 相机软件 ISP 首帧修复验收（2026-11-14）

## 结论与范围

libcamera v0.7.0 的首帧缓存初始化补丁已完成手机原生构建、GDB A/B 和
脱离调试器的六轮启停验证。原版在内存扰动下读取到无效初值；补丁版初值
全部正确，普通采集 12 次、2,520 帧均完成并正常退出。

这是软件 ISP 首帧初始化缺陷的修复验证，不是整套相机验收。MM0/RPMh
根因、GPU 停帧、图像短横线、传感器标定与桌面取景仍未解决。本轮没有
重做 MM0 同值投票跟踪，也未覆盖系统挂起恢复；没有把未复现内核故障
解释为 HF 门控候选已经修复 MM0。

## 构建与隔离

- 配方：[libcamera-first-frame](../packaging/experiments/libcamera-first-frame/README.md)。
- 源码固定提交 `b7854fd07d42168f099b5ce30d1702e0e0875bf5`，归档与补丁哈希、
  归档 commit 及正反向重放均通过核验。
- 手机原生 arm64、GCC 15.3.0、Meson 1.10.1、Ninja `-j3`；
  `debugoptimized`、`_GLIBCXX_ASSERTIONS`，完整参数见配方。
- 两个独立目录 `/var/tmp/fuxi-first-frame-20261114/{baseline,patched}`，
  分别从同一归档解出；只在 patched 应用两个文件的补丁。
- 两版分别完成 360 个 Ninja 构建步骤。各自的上游测试均为 45 通过、
  1 项预期失败、29 项跳过、0 项失败。依赖 vimc 等测试设备的跳过项
  不计为实机通过；下述 OV13B10 采集另行验证。
- 不执行安装操作；`ldd` 确认本地构建库，IPA 日志确认使用对应源码目录的
  配置。系统 libcamera 与 libcamera-base 的 SHA256 在实验前后相同。

补丁在同步 IPA 初始化成功后复制初值到缓存，同时把 IPA 初始颜色矩阵
设为单位阵。没有修改 gamma 索引公式、曝光、互连投票或内核。

## 设备与 GDB 对照

开始时运行 deb9，系统 running，无失败系统服务和 D 状态线程。核对
cam6hfclk、deb9、deb8 的启动文件与实验 DTB 后，正常 Linux recovery
重启到 `7.4.0-rc1-fuxi-cam6hfclk`。启动计数确认清零后，预先把下次默认
恢复为 deb9，回退保持 deb8，然后开始相机测试。

两版均以普通用户 fuxi 运行，使用 CPU 软件 ISP、simple 管线、
`MALLOC_PERTURB_=191` 和同一个 `verify-first-frame.gdb`。请求
4208×3120，libcamera 实际配置为 4200×3120 ABGR8888。

| 检查 | 原版 | 补丁版 |
| --- | --- | --- |
| 首帧黑电平 | 三通道均为 3.00392151 | 三通道均为 0 |
| gamma | 3.00392151 | 0.454545438，符合 1/2.2 |
| 对比度、增益 | 均为 3.00392151 | 均为 1 |
| 颜色矩阵 | 全 0 | 3×3 单位阵 |
| GDB 结果 | 黑电平检查失败，退出 1 | 全部初值通过，完成 5 帧，正常退出 0 |

原版在参数检查失败处停止，没有继续运行到数组断言；不是本轮重新捕获了
断言栈。两次 GDB 退出后均未留下阻塞，相机可继续使用。

## 脱离调试器的采集

新增设备端 `capture-matrix.sh` 固定检查实验内核、默认/回退、构建库路径、
相机枚举及内核状态。每次采集新建普通用户进程，先半尺寸 300 帧，紧接
全尺寸 120 帧；轮间空闲 10 秒。每次都核对日志中的有效帧计数和退出码。

| 轮次 | MALLOC_PERTURB_ | 半尺寸实际/请求 | 全尺寸实际/请求 | 退出码 |
| --- | --- | --- | --- | --- |
| 1、4 | 191 | 每次 300/300 | 每次 120/120 | 全部 0 |
| 2、5 | 85 | 每次 300/300 | 每次 120/120 | 全部 0 |
| 3、6 | 255 | 每次 300/300 | 每次 120/120 | 全部 0 |

半尺寸为 2104×1560，全尺寸如上调整为 4200×3120。共计 2,520 帧，
不含 GDB 的 5 帧。没有保存图像，因而本轮不评价画质、颜色或短横线。
此处“重复启停”指独立进程连续启动/退出，未覆盖同一个 Camera 实例的
反复 start/stop。

12 次采集后 CAMSS 均恢复 runtime suspended，`gcc_camera_hf_axi_clk`
enable count 为 0；未发现 RPMh batch 超时、AMC 错误、EXT4/I/O 故障。
最终无 D 状态线程或失败系统服务。timeout 只约束用户态运行，不能保证
从内核 D 状态恢复；该限制仍保留在实验说明中。
