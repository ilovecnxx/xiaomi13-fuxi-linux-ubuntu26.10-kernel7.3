## 固定来源与语义

模块来源及两份有序表核对见[单模式记录](主摄单模式核对-20261115.md)。本次只采用
已核对的电源和身份字段，不复制原厂实现或提交原厂二进制。

厂商内核固定为 MiCode `fuxi-t-oss` 提交
`6c6099a85cb3154fc8a744c17b6b9f5fd361dea8`：

- `drivers/cam_sensor_module/cam_sensor_utils/cam_sensor_cmn_header.h` 的
  `cam_sensor_power_seq_type` 明确 0=MCLK、1=VANA、2=VDIG、3=VIO、4=VAF、
  6=CUSTOM_REG1、7=CUSTOM_REG2、8=RESET、14=BOB2。
- 同目录 `cam_sensor_util.c` 将类型映射到对应 regulator 或 GPIO/MCLK；上电步骤后的
  delay 以毫秒转换为 sleep，不能把二进制 delay 直接解释为微秒。
- `drivers/cam_sensor_module/cam_sensor/cam_sensor_core.c` 的 `cam_sensor_id_by_mask()`
  先与掩码相与，再按掩码末尾零位右移。因此值 8、掩码 `0xff00` 要求
  `(id & 0xff00) == 0x0800`，不是读取两字节后直接比较 `id == 8`。

CamX 参考固定为 `36fc163a534963a5b3af52186af5efcc63401ad2`，
`chi-cdk/api/sensor/camxsensorcommon.xsd` 的 `PowerSetting.delayMs` 和
`camx/src/swl/sensor/camximagesensorutils.cpp` 的 `CreatePowerSequenceCmd()`
交叉确认毫秒字段及 configType 传递。其较旧公开枚举仅到 11；12–14 的定义以
上述小米内核头文件为准，不从旧枚举推测。

## 实现与边界

新增板级实验驱动 `drivers/media/i2c/fuxi-imx800.c`，compatible 为
`xiaomi,fuxi-imx800`。它不是通用 IMX800 管脚定义，也不是完整 V4L2 驱动。

| 步骤 | 动作 | 后续延时 |
| --- | --- | --- |
| BOB2 | 请求 3.104 V，然后 enable | 2 ms |
| VAF | L4M enable | 10 ms |
| CUSTOM2 | L7M enable | 5 ms |
| MCLK | enable，必须为 19.2 MHz | 2 ms |
| VANA | GPIO69 控制的 2.8 V | 0 |
| CUSTOM1 | GPIO66 控制的 1.8 V | 0 |
| VDIG | L2M 1.104 V | 0 |
| VIO | L2C 1.8 V | 0 |
| RESET | 释放 GPIO118 低有效复位 | 20 ms |

下电按逆序执行，CUSTOM2 后 5 ms、VAF 后 10 ms、BOB2 后 1 ms。
BOB2 电压请求与 enable 分开跟踪；存在任何未释放步骤时保留电压请求。
上电失败返回原始错误，另存清理错误；下电失败保留对应引用，清理继续处理其他步骤，
后续重复上电拒绝不完整状态，避免重复 enable。probe 退出时 devm 清理会重试剩余步骤一次，
仍失败则记录保留状态；引用跟踪不等于硬件故障恢复保证。

身份从 `0x0016` 读取两字节，按高字节在前组合并应用上述掩码；读失败保留 errno，
不匹配返回 `-ENODEV`。成功也立即 runtime suspend，不注册 media/V4L2/capture 接口，
不写传感器寄存器，不启动 CAMSS。尚未新增从此驱动执行实机循环的接口。

新增隔离 DT `sm8550-xiaomi-fuxi-imx800-id.dts`：CCI0 master1 / `0x10`、MCLK2，
关闭其他手动相机电源客户端、CCI1 与 CAMSS；不是标准或当前手机使用的设备树。
BOB2 是共享电源，本次 consumer 电压请求与本机共用者的真实相容性仍须实机验证。
供电轨名称沿用既有 DTS，标称名称不代表请求值，需以实际 constraints/读回核实。

```bash
make -C build/linux-camera-imx800-power \
  O="$PWD/work/kbuild/camera-cpas-pm-arm64" \
  ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- W=1 -j4 \
  drivers/media/i2c/fuxi-imx800.o qcom/sm8550-xiaomi-fuxi-imx800-id.dtb

cd build/linux-camera-imx800-power
python3 tools/testing/kunit/kunit.py run --arch=x86_64 \
  --build_dir=../../work/kbuild/camera-cpas-pm-kunit \
  --kunitconfig=../../kernel/experiments/camera/imx800-power/kunit.config \
  --jobs=8 --timeout=90
```

构建需先启用 `CONFIG_VIDEO_FUXI_IMX800`；KUnit 命令需要 x86 QEMU。
本次主机未装 QEMU，内核构建后在临时容器安装固定 snapshot 的 QEMU 11.0.3，
以 `kunit.py exec` 运行；测试完成已删除容器。已有 DTS 的显示 address/size 提醒
不属于本次相机节点。检查产物、日志均保留在本地 work，不提交设备资料。
