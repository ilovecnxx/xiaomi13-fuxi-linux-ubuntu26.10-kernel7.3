# 原厂功能覆盖核查

2026-11-08，检查运行内核 `7.4.0-rc1-fuxi-std2`。没有运行相机或充电实验，未写入 Android/固件分区。

## 结论

项目尚未覆盖小米 13 原厂全部能力。驱动配置、服务启动、测量值和应用场景验收是不同层次，不能相互替代。

| 功能 | 当前证据与限制 |
|---|---|
| 加速度、环境光、距离、磁场、指南针 | 既有五类读数和 SensorProxy 健康检查通过；并不代表五个独立物理芯片，指南针可由其他测量计算 |
| 陀螺仪 | 已安装 libssc 0.4.4 的 `ssccli --sensor gyroscope` 可返回有限三轴读数（help 漏列）；固件安装矩阵全零、库回退单位矩阵，轴方向、单位、运动响应和应用场景未验收 |
| 重力 | 已通过 libssc 三轴解析器按需读取；正常与 SIGTERM 中断关闭成功，轴方向、运动响应、标定和挂起恢复未验收 |
| 其他 SSC 类型 | 尚待对照原厂清单逐项核查，不能依据 CLI 帮助或已有六类读数推断全部支持 |
| NFC | 实机 `# CONFIG_NFC is not set`，未发现 `/sys/class/nfc` 设备，未完成驱动、供电/中断、用户空间通路和读卡测试 |
| GPS/GNSS | 没有 GNSS 类设备；带身份的标准 MM GPS_RAW 两轮启停已通过，最终关闭定位；无有效 fix，NMEA/AGPS 与 GeoClue 桌面定位仍未接通 |
| 显示、触摸、GPU、WiFi | 基础功能已有实测；持续功耗、全部网络场景和长期稳定性仍需单独验收 |
| 蓝牙 | 上电和 L2CAP 已验收；耳机 A2DP、通话音频及挂起恢复未完成验收 |
| 蜂窝 | 双卡注册、数据、短信及 VoLTE 来电已有实测；通话仍无声 |
| 相机 | 实验出图不等于可用相机；全尺寸启流可能阻塞互连/UFS，按用户要求暂停实验 |
| 充电 | 基础充电可用，MDY-12-EF 稳定快充未解决，不能声称达到原厂 67 W |
| 指纹 | 当前不可用；现有调查指向 TrustZone 独占，尚无可用方案 |
| 振动、红外、无线充电、反向充电、USB OTG/视频输出 | 未取得完整功能验收；需要逐项核对硬件、驱动和应用支持，不能默认可用 |

GNSS 不一定通过 Linux GNSS 字符设备接入：高通平台也可走基带 QMI LOC/PDS。
因此 `CONFIG_GNSS` 关闭本身不足以证明 GPS 不可用；本轮结合实际位置能力和无搜星结果，结论是**尚未完成卫星定位**。
基站区域信息与 WiFi/IP 定位不能用作 GPS 修复证据。

## 陀螺仪测量通路

手机已安装 `libssc2`、`libssc-bin` 和 `gir1.2-ssc-2` `0.4.4-2`，无需新增驱动或常驻进程。
`ssccli --help` 漏列 gyroscope，但发行源码 CLI 分支与安装的库均支持它。
使用 `timeout -k 2s 15s ssccli --sensor gyroscope --timeout 6` 限时采样，正常退出并收到连续三轴数据；
没有启用会输出 QMI 个人信息的 `--debug`。这仅验证静态测量通路，不代表运动响应和标定完成。

库报告 `Mount matrix provided by firmware is all 0, falling back to identity matrix`，
说明当前不能用这次测量证明手机坐标系正确。CLI 及其 protobuf 注释把 velocity 标成 `m/s`，
库原样转发 SSC 三轴数据；未独立核实实际角速度单位，不将该标签作为正确物理量或改写为已验证的 rad/s。
待现场测试各轴正反转动、静态偏置、时间戳/采样率和休眠恢复。

`scripts/fuxi-health.sh --require-sensors` 及传感器部署后的采样现在包括 gyroscope。
健康检查要求该类型的有限 XYZ 读数，并显式提示矩阵和单位限制；各类型均检查采样返回码、测量前缀及
`Unable to ...` 错误，因为上游 CLI 即使关闭传感器失败也可能退出 0。
测试只按需短时开启，结束后调用库关闭接口，不新增后台采样。

## SSC 类型属性清单

`scripts/fuxi-sensor-inventory.sh` 使用已安装的 `SSC-2` GI 与通用 `SSC.Sensor.new()`，
只进行 SUID 发现和属性请求，不调用 `open()` 或请求测量流。JSON 保存到 `work/sensor-inventory/`；
device `0.20261108.28` 提供 `/usr/libexec/fuxi/fuxi-sensor-inventory`，按需运行，没有常驻单元。
每个类型在独立进程中查询，GLib 期限 6 秒、进程硬期限 8 秒，最多 16 个固定类型；
远端总期限 135 秒，SSH 总期限 145 秒。超时子进程由 subprocess 结束并回收。
只读取库定义正确的 name/vendor/data-type 字符串属性；0.4.4 的 available/sample-rate/stream-type
GParamSpec 与 getter 类型不一致，暂不使用它们判断可用性，也不输出原始传输日志。

原六类短时测量继续由健康检查单独验证，不能把属性查询结果替代读数或运动测试。

## 重力测量通路

`scripts/fuxi-gravity-sample.sh [1..10]` 按需读取 gravity 类型，默认 3 秒；device `.29` 提供
`/usr/libexec/fuxi/fuxi-gravity-sample`。没有新增常驻服务或改动 SensorProxy、桌面和自动亮度。
通过 `SSC.SensorAccelerometer` 的构造属性指定 gravity，复用已安装 libssc 0.4.4 的三轴解析和启停接口。
公开可查的 [gravity 协议定义](https://github.com/Rivko/android-firmware-qti-sdm670/blob/20bb8ae36c93fc16bbadda0e0a83f930c0c8a271/adsp_proc/ssc/sensors/pb/sns_gravity.proto)
说明它使用标准 sensor event，六个浮点数中前三项为重力，后三项为线性加速度；这里只使用前三项。
libssc 加速度解析器接受至少三项，只发出前三项并应用库的安装矩阵，不会从本工具得到后三项。
协议注释的 m/s² 与约 9.80665 的模长仅是单位线索，未独立标定，JSON 仍标为未独立验证。
本仓库没有复制上述协议文件或修改 libssc，也没有据此宣布 linear_accel 类型可用。

初始化期限 6 秒、启流期限 4 秒、采样 1–10 秒、关闭宽限 2 秒；主机包装另有远端 30 秒、SSH 40 秒硬期限。
超时或 SIGINT/SIGTERM 取消初始化；启流中的操作等待回调后再关闭，避免先 disable 后迟到 enable。
宽限内仍无回调时明确报告 cleanup_timed_out，不能当成关闭成功。
正常和中断均请求关闭并检查确认；异常值不计入有效样本，不保存原始传输日志。
退出码 0 只用于有有效读数且正常关闭，失败/中断为非零。工具不验证运动、坐标或完整硬件覆盖。

三秒仓库版实测 14 组、安装后 17 组有限读数；安装后模长范围 9.80664949–9.80665115。
十秒请求在第三秒接收 SIGTERM，12 组读数后报告 interrupted、closed=true；正常测试为 sampled、closed=true。
本机 GI 给出 GLib.unix_signal_add 弃用提示，但本轮信号处理及关闭实际成功。
13 项回归覆盖初始化错误/迟到回调、类型不符、启流失败/超时、信号、关闭失败/超时、无效读数和期限。
主机完整结果为 322 项脚本测试（缺 GLib 开发包跳过 1 项 C 测试）及 61 项应用测试通过。
静态读数与正确关闭不代表轴向、动态响应、采样率、时间戳或挂起恢复验收，也不据此宣称省电。

## GNSS 自动诊断

运行 `scripts/fuxi-gnss-audit.sh`，通过 SSH 使用仓库版本执行检查，JSON 保存到 `work/gnss-audit/`。
设备包也提供 `/usr/libexec/fuxi/fuxi-gnss-audit`，可在手机上直接运行。
分别查询 Linux GNSS 类设备、QRTR LOC/PDS、ModemManager 公布的定位能力及 LOC 的两个只读属性接口。
每个子命令最多 8 秒，总体 SSH 执行上限 50 秒；不启动 GPS、不设置锁或模式、不请求坐标、NMEA 或基站详情。
原始命令输出不落入报告，命令失败/缺失/超时、格式异常与确实没有公布能力分别记录。
LOC 节点不存在、发现失败或有多个节点时不随意选节点调用 QMI。

2026-11-08 早期只读实测（重新初始化之前）：

- QRTR LOC（service 16，version 2）在 node 0 发布，未发现 PDS（service 6）。
- 经 qmi-proxy 的 engine-lock、operation-mode 读取均成功；这是接口可访问证据，不代表卫星定位成功。
- ModemManager 仍只有 `3gpp-lac-ci`；工具报告 `loc_readable_but_modemmanager_gps_not_exposed`。
- `satellite_fix` 固定为 `not_tested`，没有开始定位会话；当前证据不能确定 MM 初始化时未发现 LOC 的原因。

177 项主机回归和 61 项应用测试通过，含超时、缺工具、未知能力、多个节点及有 GPS 能力但无定位验收的分支。
设备包安装、运行和稳态检查见 [`持续优化记录`](功耗性能持续优化-20261108.md)。

后续初始化与限时会话检查更新了上述能力状态：MM 重新初始化后公布 `gps-raw/gps-nmea/agps-msa/agps-msb`，
但其 NMEA 配置返回 NotSupported，GPS 启动返回 GeneralError，不能把公布能力当修复。
实机对照确认 LOC 注册需要客户端身份；带身份先注册、再启动可收到报告。
新工具 `scripts/fuxi-gnss-session.sh 30` 的 30 秒窗口有 30 条 IN_PROGRESS 和 29 条卫星状态报告，
没有有效 fix，也没有原生 NMEA；信号中断与并发保护已实测，停止、释放和关闭均成功。
接口、证据、边界和后续接入见 [`GNSS 会话验收`](GNSS按需会话验收-20261108.md)。

后续 modem `.20` 已把身份注册和原生 GPS_RAW 报告通路纳入固定 MM 补丁并安装。
标准 Location.Setup 两轮（20 秒、3 秒）启停成功，报文 Start/Stop 返回 SUCCESS，最终恢复仅 `3gpp-lac-ci`、signals=no。
能力收紧为 `3gpp-lac-ci/gps-raw`；禁用中间报告，因此本次无有效 fix 时没有 IN_PROGRESS 通知。
有效报告转换已由实际回调的 C 测试验证，但尚无真实卫星成功报告，不能宣称定位功能完成或推断节电收益。

进一步检查 Ubuntu [GeoClue 源码](https://archive.ubuntu.com/ubuntu/pool/main/g/geoclue-2.0/)：
已安装的 2.7.2 及 2.8.2 在 `src/gclue-modem-manager.c` 中仍使用 MM GPS_NMEA，
单独升级不能接通仅有 GPS_RAW 的设备。标准 MM GPS_RAW 只提供时间、经纬度与可选海拔，
没有水平精度字段；GeoClue 的 locator 会丢弃精度未知的位置。桌面接入还需建立真实精度数据通路，
不能合成 NMEA、臆造精度或只转发经纬度后标记完成。本轮未修改 GeoClue 或启动定位。

## 虚拟化与 Clash TUN

- 实机未启用 `CONFIG_VIRTUALIZATION`，没有 `/dev/kvm`，目前不具备 KVM 加速。
  本次当前启动日志明确为 `CPU: All CPU(s) started at EL1`；单独开启内核配置不足以获得 KVM。
  没有修改引导层或固件；CPU 特性列表不能替代实际 EL2/KVM 可用性检查。
- Wayland 是桌面显示协议。运行 Wayland 客户端与虚拟机中运行 Wayland 桌面不同；后者还取决于 QEMU、guest 图形设备和显示后端。
- 实机 `CONFIG_TUN=y`，具备 nftables/Netfilter 支持；本次 root 身份打开 `/dev/net/tun` 后，
  `TUNGETFEATURES` 返回 29171，包含 IFF_TUN 和 IFF_NO_PI。先前 mihomo 权限核查为
  `cap_net_admin,cap_net_raw=ep`，本批未重新检查该文件能力或切换实际代理路由。
  接口可查询不代表普通用户有建网卡权限，也不能记为整条代理链路验收完成。

### 自动核查入口

`scripts/fuxi-runtime-audit.sh` 通过 SSH 运行仓库工具并把 JSON 保存到 `work/runtime-audit/`；
device `.23` 也提供 `/usr/libexec/fuxi/fuxi-runtime-audit`，按需执行，不新增常驻服务。
核查使用当前内核 `/proc/config.gz`，不可用时仅回退到相同 release 的 `/boot/config-*`；
遗漏配置保留 null，明确的 `is not set` 才记录 n，不误用其他内核配置。
启动日志只查询本次内核的 CPU 启动级别消息，最多 8 秒，原始日志不进入报告；SSH 上限 20 秒。
权限错误、缺日志、命令缺失或未识别消息均保留未知状态。

设备打开时拒绝符号链接，并用已打开描述符核对字符设备和主次设备号；随后仅发
`KVM_GET_API_VERSION` 或 `TUNGETFEATURES`，任何成功或失败路径均关闭描述符。
不发 `KVM_CREATE_VM` 或 `TUNSETIFF`，不创建虚拟机/网卡，不修改路由或代理。
KVM API 版本 12 仅表示当前执行身份可访问 API，guest 执行、Wayland guest、TUN 网卡创建
和代理链路始终独立标为 `not_tested`。QEMU 字段只表示当前 PATH 中能否找到 aarch64 系统模拟器。

11 项回归覆盖配置来源及解压上限、权限/缺失、错误设备拒绝 ioctl、ioctl 失败关闭描述符、
KVM 版本、TUN 功能位、当前启动日志边界及“接口可查不代表端到端可用”。本地完整回归为
263 项脚本测试（缺 GLib 开发包跳过 1 项 C 测试）及 61 项应用测试通过。
实机安装前后报告一致，核查结果不据此推断性能或续航变化。

## 后续验收门槛

- 全传感器：对照 Android 原厂传感器清单，逐项核对类型、采样率、轴方向、时间戳、休眠恢复和功耗。
- NFC：识别本机控制器与接线，建立供电/中断和协议通路，再测试标签读写；交通卡/支付另受安全元件及服务支持约束。
- GNSS：确认基带定位服务与访问方式，先做室外冷启动搜星/首次定位，再检查精度、重复定位、挂起恢复及功耗。
- 原厂整体功能：逐项保留明确结果与失败记录，不以一次健康检查或成功编译宣称全部支持。
