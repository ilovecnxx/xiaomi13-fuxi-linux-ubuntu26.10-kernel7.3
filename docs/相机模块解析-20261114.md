# 本机相机模块只读解析

新增 `scripts/fuxi-camera-module.py`，独立实现本机观察到的 CamX 3.5 格式子集。
只输出模式和表的统计摘要，不生成驱动寄存器表，不访问设备、不执行写入。
需要 Python 标准库；原厂二进制仅留在本地忽略目录。

```sh
python3 scripts/fuxi-camera-module.py /private/path/sensor-module.bin
python3 -m unittest discover -s scripts/tests -p test_camera_module.py -v
```

支持范围限定为 binary version 3.5.0、Parameter Parser V3.5.1 (2207122229)、
692 字节 sensorDriverData、280 字节 resolutionData 和 60 字节 streamConfiguration。
其他版本/布局直接拒绝；不是通用 CamX 反编译器。

## 已验证的结构

- 校验文件长度、三个 section 的边界/顺序、60 字节 symbol entry 的唯一 ID、
  value 范围与 alias 对应范围，按 symbol ID 解析引用，不猜测模式表序号。
- 40 字节 regSetting 使用独立的 registerData 引用；保留零地址、多值数据、
  原始操作编码和寄存器宽度，delayUs 通过引用读取，不把 presence 标志当延时。
- 可选 slaveAddr 的值宽度是 16 位，delayUs 是 32 位；值区地址可以不对齐。
  streamConfiguration 的 vc 是数组，不能把数量当成布尔字段。
- 只沿 sensorDriverData 的模式、初始化、启停和 group hold 引用统计传感器表，
  不把同一文件中的 EEPROM、OIS 或执行器表误当作传感器模式。
- 身份字段、操作、时钟等保持 `encoded` 标记。未知字段没有强行解释；
  文件尾四字节及 section 2 的语义/完整性尚未核实，明确输出
  `integrity_verified=false` 和 `hardware_verified=false`。

本轮全部六份本地 fuxi 模块解析通过：

| 模块 | 模式数 | init 寄存器记录数 | 上电/下电步骤数 |
|---|---:|---:|---:|
| OV13B10 ofilm | 4 | 130 | 6 / 6 |
| IMX800 semco | 14 | 167 | 9 / 9 |
| IMX800 sunny II | 14 | 167 | 9 / 9 |
| OV32C sunny | 5 | 1,614 | 5 / 5 |
| S5K3K1 semco | 4 | 309 | 9 / 9 |
| S5K3K1 semco II | 4 | 309 | 9 / 9 |

IMX800 数据含 8192×6144、4096×3072 等配置，CSI 描述为 3 lane、3 phase。
这些是文件中的原厂配置，不代表当前主线内核已实现对应帧率、分辨率或 C-PHY。
`outputPixelClock` 不能直接等同于 V4L2 pixel rate 或 CSI link frequency，
必须再核实本机 19.2 MHz 输入、PLL、时序和 CAMSS 接收端。
IMX800 身份编码值 8 与历史实测 0x0800 的字节顺序仍需解释；前摄身份编码为 0，
且部分表有 slave override，不能据此宣称 ID 已确认或直接写默认地址。

12 项合成测试覆盖正常摘要、角色隔离、数据宽度/延时/地址保留、16 位 slave
override、多 VC、非对齐值、alias、截断、越界、坏引用、非法 flags、NaN 和 CLI
失败行为。测试夹具完全合成，不包含原厂数据。结构检查不验证寄存器语义、
完整 checksum、器件身份、功耗时序或图像质量。

## 参考与下一步

参考公开 [sensor schema](https://github.com/comprehensive9/vendor_qcom_proprietary/blob/11se/chi-cdk/api/sensor/camxsensordriver.xsd)
中的结构名称，并逐项核对本机布局。公开旧 schema 与本机版本存在差异，
不按旧结构的偏移直接解码。没有复制第三方解析实现或导出原厂完整表。

后续优先核实主摄电源、C-PHY 接收支持和时钟，再实现可审核的 V4L2 驱动候选；
前摄和长焦还需稳定上电/ID 证据。所有硬件操作继续使用隔离内核与已验证回退。
