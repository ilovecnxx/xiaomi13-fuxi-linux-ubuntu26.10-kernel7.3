## 来源与实现对应

固定公开来源为 MiCode camera-kernel 提交
`6c6099a85cb3154fc8a744c17b6b9f5fd361dea8`：

| 来源 | 核实内容 |
| --- | --- |
| `cam_csiphy_2_1_2_hwreg.h` | 28 档数据率、3ph 表、公共配置、reset enter/exit |
| `cam_csiphy_dev.h` | trio 0/1/2 的使能位分别为 bit 1/3/5 |
| `cam_csiphy_core.c:cam_csiphy_config_dev()` | 先速率表，再三相初始化；settle 覆盖高低字节 |
| `cam_csiphy_core.c` 启动流程 | reset、lane enable、common、config、release reset |
| `cam_csiphy_soc.c:get_clk_voting_dynamic()` | 本机 C-PHY RX 时钟按 data_rate / 32 选档 |

头文件路径前缀为 `drivers/cam_sensor_module/cam_csiphy/include/`，其 SHA256 为
`2725549447a6e2376cada08a416e47044a12afab2f191e86b8f709f458627c1d`；其余文件在
`drivers/cam_sensor_module/cam_csiphy/`。保留原 GPL-2.0-only 和 Qualcomm 版权。

已用结构化提取核对压缩表展开：28 档共 1,008 个速率条目，以及 69 个三相初始化
条目的地址、值、顺序、延时均与固定来源一致。settle 项按厂商代码用调用者计数覆盖，
不使用表内占位值。公共配置为 `0x101c=0x7a`、`0x1018=1`；退出复位
`0x1000=0x0e` 后等待 3,048 微秒。全部 trio bank 按表初始化，mask 选择启用的 trio。

厂商表带宽是每 trio 的 bits/s，阈值采用其取整的 **2.28 bits/symbol**。
保留这些阈值并使用 u64，不将档位名称当 V4L2 link frequency；超过末档返回错误，
不沿用厂商兜底到末档的行为。中断继续采用 CAMSS 的全屏蔽策略，未复制厂商 IRQ enable。

## 验证边界

测试调用真实配置/停机函数，检查三个 bank、16 位 settle、超过 32 位的速率、所有
档位上下边界、单/双 trio 重映射、停止后重配，以及 17 类非法输入不写任何寄存器。
原 45 项 CPAS/CSID 测试全部保留。RAM 不模拟 CSI 电气、复位握手、DMA 或资源投票；
不能把 RAM 中的重配成功称为手机相机重开通过。

本轮复用构建缓存 `work/kbuild/camera-cpas-pm-arm64` 和
`work/kbuild/camera-cpas-pm-kunit`，实际 source 已指向 `build/linux-camera-cphy-phy`。
最终内核日志保存在本地 `work/camera-cphy-phy-20261115/kunit.log`，不提交原始日志。
完整复现命令及补丁哈希见 [cphy-phy 配方](../kernel/experiments/camera/cphy-phy/README.md)
与 [manifest](../kernel/experiments/camera/cphy-phy/manifest.json)。

   时钟选择为 link_freq / 4，均须处理 C-PHY 语义后再开放。
