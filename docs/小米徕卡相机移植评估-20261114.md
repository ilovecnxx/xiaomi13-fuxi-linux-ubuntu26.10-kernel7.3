# 小米徕卡相机移植目标与依赖

用户要求尽量完整移植小米徕卡相机。后续以原厂拍摄能力和成像体验为目标，
但目前没有已验证的 Ubuntu 原生完整移植方案。保留现有主线 Linux 路线，
先解决四摄、稳定采集、控制及照片/视频流程，同时调查原厂组件的可接入性。
不能将普通滤镜、水印或相似界面称为原厂徕卡算法移植。

## 已找到的同机型参考

1. [LineageOS-Sado fuxi MiuiCamera 配置](https://github.com/LineageOS-Sado/android_device_xiaomi_fuxi-miuicamera/tree/8b9513a780b4473c4c020e69ec58fff93835e225)。
   `proprietary-files.txt` 标注来源为 OS3.0.308.0.WMCCNXM，包含 MiuiCamera.apk、
   `libcamera_algoup_jni.xiaomi.so`、`libcamera_mianode_jni.xiaomi.so`、
   `libmicampostproc_client.so`、`vendor.xiaomi.hardware.campostproc@1.0.so`。
   `device.mk` 还安装特权权限、hidden API 白名单及公开库列表。
2. [XccJam fuxi 移植记录](https://github.com/XccJam/miuicamera-fuxi-port/tree/991169c25e3b90f8daf5ab224c0e7c77a6a7442a)。
   面向 LineageOS 23.2 / Android 16，需要 framework Camera2 兼容构造函数补丁、
   原厂 JPEG/HEIC 后处理管线及 CamX 配置。作者报告高分辨率拍照、4K30/8K24
   可用，同时明确列出杜比视界录像崩溃、1:1 徕卡水印条纹问题。
   这些是外部项目报告，未在本机复现，且不代表全部功能通过。
3. [LineageOS fuxi 组件清单](https://github.com/LineageOS/android_device_xiaomi_fuxi/blob/6f5d556c4c9231c610c85665fc6a92b2da8da2fb/proprietary-files.txt)
   列出 QTI camera provider、CamX 配置、AF 模型及多种 HDR、降噪、虚化和慢动作
   DSP 算法组件，说明 APK 只是整个相机栈的一部分。

本轮仅读取公开配置与说明，没有运行这些仓库的安装/刷机脚本，未下载或发布
其专有 APK/算法库。上述参考是 Android 集成方案，不能直接用于当前主线
CAMSS + libcamera；即使运行 Android 容器，仍需解决 camera provider、私有
metadata、缓冲及底层驱动接口，容器本身不补齐这些接口。

## 分层工作与验收

| 层次 | 当前状态 | 下一步 / 验收要求 |
|---|---|---|
| 四摄、AF/OIS、闪光灯 | 超广角已出图，其他传感器未接通 | 完成驱动、标定和稳定控制，再逐镜头拍照/录像 |
| 原厂传感器配置 | 六份本地 CamX 模块可结构化读取 | 核实电源/时钟/模式参数，不能把解析结果直接作为写入序列 |
| 普通拍照、专业控制、视频 | 实验采集，尚无完整用户流程 | JPEG/RAW、曝光/白平衡、对焦、保存回看、编码和音画同步 |
| 徕卡色彩、黑白、原厂人像/夜景/HDR | 未接入原厂实现 | 分别定位算法、调校、标定与运行依赖；逐项比较真实输出 |
| 原厂 MiuiCamera 界面 | 找到 Android 适配参考 | 明确 Android framework/服务依赖，验证可行入口后再做兼容实验 |
| 高规格录像、杜比、水印等 | 当前无本项目验收 | 先核对本机原厂实际支持范围，再验收编码、元数据、画面与长录 |

原厂完整体验目前最成熟的参考仍是 Android 原厂栈或同机型 Android 移植。
这不是已完成的 Ubuntu 功能，也不自动改变本项目的内核与系统架构。
若后续证据表明必须引入 Android HAL/运行环境才能推进，应单独记录其体积、
维护成本、接口依赖和实机结果，再决定是否形成额外兼容路线。

## 本机证据边界

本地六份传感器模块已保存，可用于只读研究；本地 OS3.0.309 原厂目录未找到
`super` 镜像，尚未取得该版本完整的 MiuiCamera/后处理组件集合。
历史 Android 记录是 LineageOS，不能假设当前 Android 分区已经安装原厂徕卡相机。
本轮保持手机在 Linux deb9，没有切换 Android 或修改其系统分区。
公开仓库只纳入自有工具、格式说明和验证结论，不纳入原厂二进制或完整寄存器表。

本轮基础进展见[模块解析](相机模块解析-20261114.md)和
[Adreno EGL 验收](相机重启实验-20261114.md#手机恢复后的-adreno-验证)。

## 主摄 C-PHY 前置缺口

本机 IMX800 模块的已解析模式使用三条 C-PHY trio。进一步检查 cam6 源码发现：

- `camss.c:camss_parse_endpoint_node()` 明确拒绝非 D-PHY 总线。
- `camss-csiphy.c` 的 generic PHY 路径固定设置 `PHY_MODE_MIPI_DPHY`；
  `phy-qcom-mipi-csi2-core.c` 同样拒绝其他模式，配置校验使用 D-PHY 参数。
- SM8550 使用的 `camss-csid-680.c` 虽定义 `CSI2_RX_CFG0_PHY_TYPE_SEL`，
  实际接收配置尚未按 C-PHY 类型设置该位，也未传递完整的总线类型状态。

因此需要贯通端点/trio 描述、PHY 时序与速率换算、对应硬件初始化和 CSID 接收
模式，再结合本机 19.2 MHz 时钟验证传感器输出。`3ph` 文件名或寄存器常量存在
不代表驱动已经支持 C-PHY；不能只放开端点类型检查或套用 D-PHY lane 数计算。
本轮没有向 IMX800 写入模式表，也没有声称实现主摄或原厂算法。

超广角重复启流的 MM0 仍是另一项阻塞；新增
[RPMh 批量请求生命周期候选](相机RPMh生命周期-20261114.md)
只修复超时后的内存所有权，不代表采集恢复完成。
