## 修改范围

原先 `vfe_put()` 关闭本地时钟后才释放 CAMSS runtime PM，最后一个 VFE 的引用
也不能代表所有 CSID/PHY/TPG 用户退出。新增 CPAS 共享时钟引用由 CAMSS 整体
runtime PM 持有，避免在 VFE 本地时钟关闭后无时钟访问 CPAS。

- 启动：显式开启 HF，提交现有带宽，设置 CPAS AHB/CAMNOC 为已有 VFE 最低
  80/300 MHz 并开启，临时开启 ICP，写入启动请求并等待 QACCEPTN。
- 最后一个用户退出：共享时钟仍开启时临时开启 ICP，写入停止请求，等待
  QACCEPTN/QDENY 均为 0，再撤掉带宽并关闭共享时钟，最后关闭 HF。
- 仅对实测 Titan 780 / CPAS 1.0.0 及已知控制位写寄存器。无 CPAS 资源的
  旧 DTB 保留原路径；有资源时 ICP/HF 必须可获取，lookup/defer 错误传递。
- 停机失败返回 `-EIO`，保留共享时钟，使 runtime PM 拒绝新用户；需要重启。
  这是阻止继续误用的故障处置，不是硬件自动恢复。

HF 使用显式时钟引用，因为 `pm_clk_resume()` 不传递每个时钟的开启失败。
时钟准备、开启和调频失败均可阻止上层继续启动；尚未启动生产者时清理已获取资源，
保留原始启动错误。

## 尚未解决的边界

`qcom_icc_set()` 仍丢弃 BCM commit 错误，ICC 核心可能重提旧投票；本候选没有
修复这些行为，不能保证真实 RPMh 超时后的硬件状态。停机带宽处理若中途失败，
此前路径的投票可能已撤掉，但共享时钟保留，后续启动被阻止。实机检查必须单独
拒绝 RPMh/AMC 超时，不能只依据消费者函数返回 0。

10 ms 是寄存器轮询预算，不是所有时钟/RPMh 操作的完整上界。程序 timeout
无法保证终止 D 状态任务；新候选先做一轮 RAW，确认停机及健康状态后才继续。
