来源：子 agent 只读调研 `build/linux/sound/soc/qcom/qdsp6/`。**行号和结论未经主会话逐条回读源码核对**；标【事实】的是子 agent 称在代码/文档中看到的，标【推测】的是它的推断。不碰手机，不向 ADSP 发任何命令。

前置文档：`docs/调研-通话音频-Android抓包-20261101.md`、`docs/调研-ACDB语音图-20261101.md`、`docs/调研-通话音频-缺口-20261101.md`。

## 1. 可复用的部分（路径相对 sound/soc/qcom/qdsp6/）
- 【事实】图模型是通用的：`audioreach_graph_info` → `audioreach_sub_graph` → `audioreach_container` → `audioreach_module`（audioreach.h:882-923），模块带跨图连线数组（上限 8）。
- 【事实】`audioreach_alloc_graph_pkt()`（audioreach.c:482）一次 in-band `APM_CMD_GRAPH_OPEN`，含 SUB_GRAPH_CONFIG / CONTAINER_CONFIG / MODULE_LIST / MODULE_PROP / MODULE_CONN，与 ACDB 里的参数 id 一致，支持 N 个子图。
- 【事实】子图 scenario id 原样透传，`APM_SUB_GRAPH_SID_AUDIO_VOICE_CALL 0x3` 已定义（audioreach.h:472）。
- 【事实】打开路径：`q6apm_graph_open()`（q6apm.c:718）→ `q6apm_get_audioreach_graph()`（q6apm.c:41）按 `graph_id` 查 `graph_info_idr`。prepare/start/stop 走 `audioreach_graph_mgmt_cmd()`（q6apm.c:95），一次带上图里所有 SG id。
- 【事实】`graph_info` 目前只从 tplg 创建（topology.c:361-364），没有运行时构建 API。

## 2. 与语音图冲突的硬编码
- q6apm.c:731-750：找 SH_MEM/RD_WR_SHARED_MEM 端点，语音图没有，`is_push_pull_mode` 不会置位（影响小）。
- q6apm.c:443-466 + audioreach.c:1467：`q6apm_graph_media_format_pcm()` 对已知 mid 下发同一份 PCM 格式。若语音图含 MFC/SAL 会被配成 PCM 速率/声道，语音需要 NB/WB 单声道。新 mid（700100e、700100f、700105a、7001011、700103c、7001028）不在 `MODULE_ID_*`，会被跳过。
- topology.c:895-920、1018-1048：tplg 只接受有限的 module/widget 类型，语音模块会 -EINVAL 或 "not yet supported"（仅走 tplg 方案时相关）。
- audioreach.c:757-765：CODEC_DMA 的声道掩码来自 hw_params，无 PCM 流时为 0。
- 【事实】跨 SG 的连线只有 FE↔BE 一条（topology.c:1205-1228）；ACDB 文档称 SG 间连线"未解析"。
- 【推测】语音 GRAPH_OPEN 可能超过 GPR intent 512 字节（sm8550.dtsi:3254 `qcom,intents = <512 20>`），未验证。

## 3. 缺什么（全部【事实：代码里没有】）
- `VCPM_MODULE_INSTANCE_ID 0x4` 已定义（audioreach.h:48）但无引用；无 VSID/0x080011bc/0x08001310/0x0800116b；无 q6voice 相关文件。
- CODEC_DMA 端点的 0x0800108a、0x08001176（TX）与 0x0800106a、0x0800113c（RX）内核不认识；INTF_CFG 具体值在 ACDB 未解析的 MTDE 块（miid 0x43ad）。

## 4. 建议的新增（【推测】，待用户批准才动手）
1. audioreach.h：加 `PARAM_ID_VCPM_VSID 0x080011bc`、`PARAM_ID_VCPM_STATE 0x08001310`、`PARAM_ID_VCPM_PATH_ENABLE 0x0800116b` 及对应 packed 结构、新 MODULE_ID、SET_CFG 大小宏。
2. audioreach.c：`audioreach_vcpm_set_vsid/_state/_path()`，仿 `audioreach_send_u32_param()`（audioreach.c:778-800），目标 miid 固定 0x4，经 `q6apm_send_cmd_sync(apm, pkt, 0)` 发，不需要 `q6apm_graph`。
3. q6apm.c/.h：运行时注册 TX/RX 两张图到 `graph_info_idr`（或写进 tplg 的专用 DAI index），导出 `q6apm_voice_start(vsid)` / `_stop()`：两次 `q6apm_graph_open()`，只对 CODEC_DMA 端点设固定格式，prepare → start，VCPM SET_CFG 顺序按抓包（推测：VSID 先于 prepare，`{vsid,2}` 先于 start，`{vsid,1}` 之后）。
4. 前端：最小方案是 ALSA kcontrol（"Voice Call Start"，参数 VSID + 布尔），不需要 PCM。
5. 后端 DAI：RX_CODEC_DMA_RX_0 / TX_CODEC_DMA_TX_3 已被 fuxi 的 WCD 链路使用（sm8550-xiaomi-fuxi-audio2.dtsi:60,76）。codec 侧 DAPM 通路需用户态 mixer 打开，是否需要专用 dai-link【未验证】。
6. 用户态：UCM 加 Voice verb、通话时启停守护进程（oFono/MM 侧信号 → kcontrol）。

## 5. 未验证的关键点
- ADSP 是否接受缩减版语音图、in-band GRAPH_OPEN 的大小上限、模块间真实连线、INTF_CFG 数值。
- 以上任一项失败，都只能靠上机试验确认，属于"向 ADSP 发命令"，**需先问用户**。
