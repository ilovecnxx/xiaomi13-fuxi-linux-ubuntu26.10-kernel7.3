## 发现的缺陷与修复：Chromium 重启后起不来

**现象**：`fuxi-mobile-chromium.service` 启动 1 s 内退出，Chromium 退出码 21，服务 inactive。

**根因**：用户资料目录 `~/.config/chromium-fuxi-mobile/` 里残留 10-30 会话的 `SingletonLock`
（指向 `localhost.localdomain-20634`）。重启后主机名变为 `xiaomi13`，Chromium 的 process-singleton
检查按主机名比对，认不出是同机旧锁，报 “profile appears to be in use … on another computer” 后退出 21。

**修复**：`work/chromium-mobile/fuxi-mobile-shell.py` 新增 `clear_stale_profile_lock()`——启动前读取
`SingletonLock` 里记录的 PID，进程不存在时清掉 `SingletonLock` / `SingletonCookie` / `SingletonSocket`；
PID 仍存活则保留锁。已部署到手机（备份 `fuxi-mobile-shell.py.bak-20261104`）。

**验证**：清空后重新构造一个指向死 PID 的假锁，启动服务 → 日志出现 `cleared stale chromium profile lock`，
服务 active、8 个 Chromium 进程、CDP `probe.py` 返回页面标题 `Example Domain`、`b: true`（移动外壳已注入）。

## 缺陷：自动旋转方向相反（已修，待物理复验）

**现象**：整机旋转时屏幕朝相反方向转（用户报告「上下左右全部颠倒」）。

**根因**：加速度计的固件 mount matrix 全零，`iio-sensor-proxy` 退回单位阵；
实测传感器坐标与面板相差 180°，因此判断出的方向整体反相。

**修复**：在 `ssc-accel` 所在设备（`fastrpc-adsp`）的 udev 规则里提供
`ACCEL_MOUNT_MATRIX=-1,0,0;0,-1,0;0,0,1`（`work/rootfs-overlay/etc/udev/rules.d/81-fuxi-ssc.rules`）。
`iio-sensor-proxy` 会优先采用该属性，不需要重编 SensorProxy。设备上已 reload 规则并重启服务，
`udevadm info` 可见该属性。

**验证**：干净重启（重新写入 `recovery_b` 启动）后自动旋转方向正确，用户确认。

注意：改完当时不生效且方向恒为 `undefined`，原因是反复 restart `iio-sensor-proxy` 后
SSC 会话状态残留（调试日志里出现大量 `Message 130`），必须整机重启才恢复正常。
以后改这条规则要重启设备验证，不要只重启传感器服务。

**已知问题**：旋转切换时屏幕会短暂黑屏约一瞬（DSI 重新配置），dmesg 无 DSI 报错，
属合成器切换输出模式时的正常现象；如需消除要改 mutter/Phosh 的旋转提交方式，暂不处理。
