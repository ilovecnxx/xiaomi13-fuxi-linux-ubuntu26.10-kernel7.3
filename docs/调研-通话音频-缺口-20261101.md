# 通话音频缺口调研（只读，2026-11-01）

范围：小米 13（fuxi，SM8550），主线 7.3.0+（#222 modem16-epmap）。只读命令，未改动手机和仓库其他文件。
标记：【已证实】= 在下列文件里看到；【推测】= 推断或未验证。

## 1. 手机 rootfs（sda33）上的音频相关文件
- 【已证实】ADSP 固件：`/lib/firmware/qcom/sm8550/xiaomi/fuxi/adsp.mdt` + `adsp.b00..b58`、`adsp_dtb.*`、`adspr.jsn`、`adsps.jsn`、`adspua.jsn`（audio_pd 带 `avs/audio` 服务）。modem 固件同目录 `modem.*`。目录里没有 cdsp.*（CDSP 固件未装，与语音无关）。
- 【已证实】拓扑：只有 `/lib/firmware/qcom/sm8550/Xiaomi-13-tplg.bin`（38036 字节，10-29 由 `scripts/fuxi-audio-tplg.sh` 从 SM8550-QRD 拓扑改出）。对它 `strings` 只见 MultiMedia1-6、SECONDARY_MI2S_RX、WSA/RX/VA/TX CODEC_DMA；没有 voice/vcpm/vsid/incall。
- 【已证实】手机上没有任何 `*.acdb`、`*acdb*`、其他 `*.tplg`（find / -xdev 无匹配，仅有无关的 flutter 文件）。
- 【已证实】ACDB 只在主机仓库：`work/firmware-sensors/acdb/kalama_mtp/Tutu_acdb_cal.acdb`（2.7 MB）和 `Tutu_workspaceFileXml.qwsp`，来源见 `work/android-device-fuxi/proprietary-files.txt:4-5`（`odm/etc/acdbdata/Tutu/...`）。其中有 28 条 `Voice_Call_Tx_VSID_VSID_DEFAULT` 等语音校准条目，说明手机 ACDB 里有通话校准数据。
- 【已证实】UCM：`/usr/share/alsa/ucm2/conf.d/sm8550/Xiaomi-13.conf` 和 `/usr/share/alsa/ucm2/Qualcomm/sm8550/Xiaomi-13/{Xiaomi-13,HiFi,HiFi-speaker,Xiaomi-13-wcd,Xiaomi-13-speaker}.conf`，这些是自己写的。只有 HiFi verb，没有 Voice Call verb。已有 Earpiece 设备（GPIO68 RCV MUX）。系统 alsa-ucm-conf 1.2.16.1 里 sm8550 只有 SM8550-HDK，也没有 voice verb（grep voice/call/modem 无命中）。
- 【已证实】手机当前 ALSA 声卡 Xiaomi-13（`/proc/asound/pcm`）：MultiMedia1/2/5/6 播放、MultiMedia3/4 采集、一个 compress 设备。后端 SECONDARY_MI2S_RX、RX_CODEC_DMA_RX_0、WSA_CODEC_DMA_RX_0、VA/TX_CODEC_DMA_TX。没有语音前端 PCM。
- 【已证实】内核是单体（`/proc/modules` 不存在），所以音频驱动都是内建。`/sys/bus/gprbus` 路径不存在，总线名可能不同，未深究；声卡已能注册并出声，GPR 通路可用。

## 2. 内核树 build/linux
- 【已证实】`sound/soc/qcom/qdsp6/` 有 audioreach.c、q6apm.c、q6apm-dai.c、q6apm-lpass-dais.c、q6prm*.c、q6afe*/q6asm*/q6adm*（旧 APR 路径）、q6usb.c、topology.c、q6routing.c。`sound/soc/qcom/` 有 sc8280xp.c（含 `xiaomi,fuxi-sndcard`，sc8280xp.c:641）、sm8250.c、sdw.c、common.c 等。没有 q6voice*、q6mvm、q6cvs、q6cvp。
- 【已证实】语音相关符号只有：`APM_SUB_GRAPH_SID_AUDIO_VOICE_CALL 0x3`（audioreach.h:472）、`VCPM_MODULE_INSTANCE_ID 0x4`（audioreach.h:48，已定义但全树无其他引用）、uapi `APM_SUB_GRAPH_SID_VOICE_CALL`（include/uapi/sound/snd_ar_tokens.h:19）。topology.c:372 解析 SCENARIO_ID，audioreach.c:372 下发。没有 VSID 参数下发，没有 CS-voice/incall DAI，dt-bindings 里没有 voice 后端。
- 【已证实】fuxi DTS 音频：`arch/arm64/boot/dts/qcom/sm8550-xiaomi-fuxi-audio.dtsi`（CS35L41 双功放，Secondary MI2S，q6prmcc SEC_MI2S_IBIT 时钟，RCV 开关）；`sm8550-xiaomi-fuxi-audio2.dtsi`（WCD9385、WCD RX/TX codec dma 链路，RX_CODEC_DMA_RX_0 / TX_CODEC_DMA_TX_3）；`sm8550.dtsi:3251` 的 gpr 节点含 q6apm、q6apmdai、q6apmbedai、q6prm。已启用后端：SECONDARY_MI2S_RX、RX/TX codec dma。没有 voice 后端，也没有 BT/SCO、麦克风 VA 之外的通话路径描述。
- 【已证实】厂商 DTB（`work/device-info/fuxi-live.dts:26841`）声卡 `qcom,kalama-asoc-snd` 的属性里没有 voice 专用字段；厂商通话走用户态 PAL 流 PAL_STREAM_VOICE_CALL，不靠内核 dai-link。

## 3. 基带期望什么
- 【已证实】ADSP 固件含语音电源管理模块 VCPM：`adsp.b46`（vcpm.c、vcpm_state_control.c）、`adsp.b43/b44/b47/b54`（vcpm_clk_utils.c、AUD_VCPM_CLK_CTRL）；`adsp.b43` 含 `VSID-%lu`、EAMR/AMR-WB+ 解码模块；`adsp.b46` 含 fvsam_voice_rx。说明 ADSP 侧语音子图能力在固件里。
- 【已证实】modem 固件含语音代理 `vagent.c`：日志串 `VAGENT: ASID:[%d] VSID:[0x%08x] granting resource to client[%s]`，另有 103 条 cvd 相关串、EVS/ims_rtp 串（`modem.b*`）。modem 按 VSID 管理语音资源并向"客户端"授予资源。客户端是谁（ADSP 的 VCPM、AP 的 PAL，还是两者）没有从字符串里确定。【推测】
- 【已证实】厂商用户态配置 `work/android-device-fuxi/config/audio/resourcemanager_kalama_mtp.xml:123-133`：`config_voice` 的 vsid 0xB3000000，mode_map 把 0x11C05000、0x11DC5000、0x12006000、0x121C6000 映射到 0xB3000001。`handoff` 记录 NAS 实测的主卡/副卡 voice_system_id 正是 0x11C05000 / 0x11DC5000（docs/目标-M5.md 15:09 节）。所以 VSID 已知，不需要抓包就能拿到。
- 【已证实】同文件有 `PAL_STREAM_VOICE_CALL` 的设备配对（handset-dmic-endfire、voice-headphones 等），`work/audio-reference-20261029/mixer_paths_kalama_mtp.xml:693-735` 有 voice-handset / voice-speaker 路径。说明厂商是 AP 侧 PAL 用 VOICE_CALL 流 + 设备路径 + VSID 来驱动的。
- 【推测】结合已有调研（docs/目标-M5.md 通话音频调研节）：基带内部处理 IMS/RTP/EVS 编解码，经 ADSP 的语音子图出到 CODEC DMA；AP 必须做的是 (a) 建立语音 RX/TX 子图并带上 VSID（VCPM 参数 `VCPM_PARAM_ID_VSID 0x080011BC`），(b) 设置后端设备（听筒/扬声器/麦克风）与 ACDB 校准，(c) 在通话开始/结束时启停。AP 不搬运语音数据。
- 外部来源（web 搜索，只验证了大意）：q6voiced 的说明称"通话音频直接从 modem 路由到音频设备，用户态只需启动音频流"（https://github.com/alexander-pav/q6voiced）；postmarketOS 的 enchilada（SDM845）issue 称通话有连接但无声，原因是 q6voice 未移植（https://gitlab.com/postmarketOS/pmaports/-/issues/1338）；MSM8916 通话音频合并请求（https://gitlab.com/postmarketOS/pmaports/-/merge_requests/1233）。这些是旧 APR 平台，GPR/AudioReach 平台上没有找到已合并的主线语音支持。没找到 linux-arm-msm 上的 SM8550 voice 补丁，这一点只能算"未发现"，不能算"不存在"。

## 4. 最小缺口清单（按顺序）
1. 内核：q6apm 语音子图支持。需要新 DAI（语音 RX/TX 前端，hostless）、topology/ARC 里语音子图（SID 0x3）及 VCPM 模块实例，以及向 VCPM_MODULE_INSTANCE_ID(0x4) 发 VSID 参数的接口。【已证实缺失】。工作量 2–4 周，难点在 VCPM 参数格式要靠逆向。
2. 拓扑：语音子图需要进 `Xiaomi-13-tplg.bin`（或另一份 tplg）。可用 audioreach-topology 工具自己写，但模块 ID 与连接要对 ADSP 固件的实际能力。1–2 周，含在 1 里。
3. ACDB：厂商 ACDB 在 `work/firmware-sensors/acdb/kalama_mtp/`，需要 AGM/ACDB loader 或手工把校准写入 ADSP。若不加载 ACDB，可能有声但音量/回声消除/降噪不对。【推测】1–3 周，可晚做。
4. 用户态：UCM 加 Voice Call verb（Earpiece/Speaker/Headset 设备 + 开关 PCM 的 mixer），以及一个监听 MM/QMI VOICE 通话状态的小守护进程，通话时启停语音流。3–5 天。
5. 麦克风/听筒路径：UCM 已有 Mic1/Mic2/Earpiece，但通话用的 dmic/降噪麦配置还没验证。1–2 天。

可在不进 Android 的前提下测试的部分：
- 3、4、5 的用户态和 UCM 逻辑；
- 主线 q6apm 上先手工拼语音子图（用 `apm` 命令行或自写 ioctl），用 SID 0x3 + VSID 0x11DC5000 起图，观察 ADSP 是否接受（只读观察 dmesg 错误码）；这会向 ADSP 发 GPR 命令，不是只读，需要用户批准才能做。
- 通话时 modem 是否向 ADSP 发起语音会话：靠 ADSP/GPR 日志，当前主线内核无此日志，需要加调试，不属于只读。

需要进 Android 才能做的：确认 VCPM 参数格式、语音子图模块 ID 与连线（抓 GPR 包）。离线线索：`Tutu_acdb_cal.acdb` 的 strings 能看到 `DeviceTX_..._StreamTX_Voice_Call_Tx_VSID_VSID_DEFAULT` 这类图名（校准键），但 `Tutu_workspaceFileXml.qwsp` 是二进制（`file` 报 data，strings 无 voice 字样，可能压缩或加密），不能直接读。从 ACDB 还原子图模块 ID 的可行性【推测】偏低，抓包仍是最可靠的办法。

## 5. 结论
- 缺口主要在 AP 侧内核（语音子图/VCPM 下发）和用户态启停，不在固件或 VSID。基带与 ADSP 固件已具备语音能力。
- 下一步（离线、零风险）：用 `Tutu_acdb_cal.acdb` 的 Voice_Call 键列表和 audioreach-topology / audioreach-graphservices 上游源码（需联网取）列出 VCPM 参数与语音子图模块，再决定是否需要 Android 抓包。
