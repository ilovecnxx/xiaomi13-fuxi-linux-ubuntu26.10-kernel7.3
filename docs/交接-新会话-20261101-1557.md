## 5. 已解决的问题
- 卡 2 IMS 不注册的根因：基带对 770 服务分别发 sub1 和 sub2 两条 Start Connection，81voltd 一律调 `mm_modem_create_bearer`，而 MM 的 WDS 不绑订阅，所以卡 2 的 PDN 被建在主卡上。上一版 §7.4 里多出来的 `IMS` bearer 就是这个（voltd-debug-run1-full.txt、after-cycle-state.txt）。修复见 §4 的补丁，验证【未做】。
- 卡 1 IMS 掉线后的恢复：`systemctl stop 81voltd; systemctl restart ModemManager; systemctl start 81voltd`，约 65 s 后 connected 且 IMS registered（restore-mm-restart.txt、restore-verify.txt）。

## 6. 已尝试且失败的方案（不要重试）
- `mmcli -m any --set-primary-sim-slot=2`：返回成功，但什么都没变【已证实】。原因是双卡都 ACTIVE 时，MM 把最后一个 ACTIVE 卡槽当成"当前卡槽"，于是做了空的 SwitchSlot（switch.txt、poll.txt、mm-shared-qmi.c `uim_switch_get_slot_status_ready`）。
- 在手机上运行 `81voltd --help`：它不解析参数，直接又起了一个实例【已证实】。已杀掉。不要带任何参数运行 81voltd。
- 单独 `systemctl restart 81voltd`：主卡 IMS 掉线且不自愈（Ipv6OnlyAllowed / call-already-present，因为旧 bearer 没释放）【已证实】（voltd-debug-run1*.txt）。
- 主卡 IMS 掉线后做射频循环（-d → low → on → -e → usage data）：2.5 分钟仍未恢复【已证实】（restore-cycle.txt）。
- NAS Get Serving System (0x0024) 绑定 sub2 后仍返回主卡数据【已证实】；查副卡用 Get System Info (0x004D)。
- PDC Get Config Info 0x0029 原始请求返回 QMI error 1【已证实】；MBN 名称对照 `qmicli --pdc-list-configs`。
- GI 的 Device "indication" 信号给的是原始字节，不是 QmiMessage；ClientPdc 没有 "indication" 信号【已证实】。
