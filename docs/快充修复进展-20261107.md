- UCSI soft reset、PD hard reset 均未恢复 PD。用户 20:11 重插后仅恢复 DCP 基础充电；重启和原内核对照仍无 PD，见下方复测记录。
- 20:21 用户给充电头断电重接后恢复 PD。chg3 启动后 PD 保持正常，实际输入仍约 5 V / 1.4 A（6.9 W）。
- 未伪造充电器认证结果。测试了不超过固件上限的输入电流请求，但实际限流未提高，结束后恢复 1.5 A；未修改温控策略。
- Android/固件分区及 recovery_b 未写入；仅更新 Linux 分区内的内核包和设备支持文件。

## 实现

内核隔离工作树 `~/.cache/fuxi-charge74`，分支 `fuxi/charge-7.4`，
基于收敛树 `a5dcbb9cc`，提交 `89846aa3d`。仅改 `drivers/power/supply/qcom_battmgr.c`。
相机和语音工作树没有混入本次构建。

- 新增 fuxi 专用 `xiaomi/` 属性组；认证写接口权限 0600。
- 支持 52 字节电池摘要请求和 32 字节 UVDM 多字请求。
- 保持 GLINK 请求互斥，匹配 GET opcode/属性号，检查 12/20/40 字节响应与错误码。
- 当前官方模块的 SET ACK 不保证回显属性，因此只按 SET opcode 和长度匹配；其余 GET 仍按属性匹配。
- 属性编号采用当前 309 固件对应值；未直接照搬旧版 `fuxi-t-oss` 枚举。

补丁：`work/patches/charging-auth-20261107/0001-fuxi-battery-mipps-auth.patch`。

设备包新增 `fuxi-mipps-auth`、systemd 服务和 udev 插拔触发。协议及公开密钥候选来自
Armbian `c95374efd50807424c906e885d3b2c0452c27ba4`，GPL-2.0-only，包内附来源与许可证说明。

本机只有一个电量计，跳过 sheng 的 slave 电量计步骤。程序只在摘要通过后写 `authentic=1`；
保留已认证状态，等待异步摘要更新，并检查插拔变化。测试发现反复重新挑战不能稳定完成，
因此不能为了复测而无条件重新验证已经认证的电量计。

自动服务固定使用 `--battery-only`；Type-C 角色切换仅在显式 `--swap-data-role` 时执行，
不作为日常默认行为。UVDM 认证尚未验收，不能据此宣称支持 MiPPS 或 67 W。

## 充电头断电与 chg3（20:21 起）

用户给充电头从插座断电后重接，deb5 恢复 `real_type=6`、`PDO2=184620`、
Type-C `supports_usb_power_delivery=yes` / `power_operation_mode=usb_power_delivery`。
输入 4.952 V / 1.397 A，约 6.92 W，电池 61%、净入电 +1.26 A、25.7 摄氏度。
这只证明 PD 链路恢复，手机仍未协商高压快充。

在不切换数据角色的情况下，以已有 debugfs 发送充电器版本查询（XM 属性 13、值 0）。
SET 返回成功，但 UVDM_STATE 仍为 0，ADAPTER_ID/SVID 仍为 0；ACK 不能证明充电器完成了查询。

核对官方 fuxi `qti_battery_charger.c` 后确认，原厂支持通过 USB 属性 5 设置 ICL，
当前主线描述符只有 getter。同时发现 UCSI debugfs 固定请求 24 字节响应，超过旧版 UCSI 的
16 字节上限，导致 GET_CAPABILITY / GET_PDOS 在发送前即返回 EINVAL。

chg3 在 chg2 基础上补齐：

- `ddd260be1`：仅对 fuxi 提供 INPUT_CURRENT_LIMIT setter；要求在线、USB_TYPE_PD、正值且不超过现场重新读取的固件 CURRENT_MAX；保留 GLINK 锁并检查 SET 响应长度/错误码。没有自动提高电流的服务。
- `e3ebcdbc2`：UCSI debugfs 响应请求长度限制为协议版本允许的大小。
- 补丁：`work/patches/charging-current-20261107/`，应在电池认证补丁之后应用。

```sh
FUXI_KTREE=~/.cache/fuxi-charge74 FUXI_KOUT=~/.cache/fuxi-charge74-out scripts/fuxi-build-deb.sh chg3
make -C ~/.cache/fuxi-charge74 O=~/.cache/fuxi-charge74-out ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- LOCALVERSION=-fuxi-chg3 W=1 drivers/power/supply/qcom_battmgr.o drivers/usb/typec/ucsi/debugfs.o
```

完整内核包和以上两个 `W=1` 目标均通过。源码树无未提交修改，HEAD `e3ebcdbc2`；
config SHA256 与 chg2 相同。chg3 deb SHA256：
`7df52073117a7745b1a781ada034423cb5a5a7d40e04875e9032fe29d75c370b`，设备端安装前校验一致。
仅安装 Linux 内核包，经 recovery 路径启动，未刷写 recovery 或固件分区。

实机结果：

- chg3 正常启动，电池摘要再次通过，AUTHENTIC=1，PD 连接保持。
- GET_CAPABILITY 和 GET_PDOS 已能执行，读取到固定 PDO `0x0a01912c`（5 V / 3 A）、`0x2d12c`（9 V / 3 A）、`0x4b12c`（15 V / 3 A）、`0x64145`（20 V / 3.25 A）。偏移 4 查询返回相同原始缓冲区，debugfs 未暴露实际响应长度，不能据此断言完整 PDO 数或有无 PPS。
- ICL 写入 0、-1 返回 EINVAL，超过固件 2 A 上限的 2000001 uA 返回 ERANGE。
- 20:33:41–20:34:26 依次请求 1.6 / 1.8 / 2 A，各观察 15 秒。SET 均无错误，但读回有效 ICL 始终 1.5 A，实际输入约 1.397 A / 4.946–4.958 V。电池 26.5–26.6 摄氏度，未观察到提速。结束后显式恢复 1.5 A。

- 未写 PD_VERIFED=1、未再次切 host 数据角色、未部署自动限流策略。

结果仍是 **快充未修复**：内核控制/查询接口已补齐，但固件继续选择 5 V 并保留 1.5 A 限流。

## MDY-12-EF 型号确认与握手复测（20:45 起）

用户确认充电头为小米 **MDY-12-EF**。已核对充电头网的
[拆解报告](https://www.chongdiantou.com/archives/96175.html)：这是 67 W 定制 USB-A 充电器，
接口舌片前端有特殊触点，协议芯片为南芯 SC1832XM，同时支持小米私有快充与 PD。
文章中的芯片 PD 3.0 能力不能单独证明此充电器在当前连接下提供 PPS；不能将其当作普通 C-C PPS 适配器。
用户尚未确认线材是否为配套的原装 6A A-C 线。

在 PD 保持在线且不切换数据角色的条件下，做了认证开始信号对照：

- 写 `verify_process=1`，等待 1 秒，随后发送 `request_vdm_cmd=1,null` 版本查询。
- 每 0.5 秒读取认证状态，共 8 次。开始标志始终读回 0；UVDM 始终为 `0,Null`，
  `adapter_id=0`、`adapter_svid=0`、`pd_verifed=0`。没有观察到充电器完成查询。
- `finally` 中写回 `verify_process=0`，末次读回为 0；PD real_type 始终为 6。
- 对当前原厂 `qti_battery_charger.ko` 反汇编复核：VERIFY_PROCESS 属性号确为 12；
  标量 SET 为 24 字节，battery_id/property/value 分别位于偏移 12/16/20，XM SET opcode 为 0x51。
  版本查询用属性 13、值 0，与当前实现一致。尚未发现这一段的编号或报文布局不匹配。
- SET ACK 仍不能证明状态生效；也不能据此认定固件永久拒绝所有 SET，或确诊某个固定限流原因。
  未把此次未生效的开始标志试验加入自动服务。

UCSI 只读补查：GET_CONNECTOR_CAPABILITY 的低 32 位为 `0x3fe7`；
GET_CABLE_PROPERTY 返回 EOPNOTSUPP（95），无法用该接口确认线材额定电流。
GET_CONNECTOR_STATUS 和偏移 4 的 GET_PDOS 返回缓冲区包含零值与旧数据，
debugfs 没有实际返回长度，不能将这些原始内容直接作为当前连接状态或 PPS 能力的结论。
