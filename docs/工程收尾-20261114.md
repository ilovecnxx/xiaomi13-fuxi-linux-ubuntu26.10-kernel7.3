## 外部阻塞与接续

1. 网络：`git ls-remote origin refs/heads/main` 无法解析 `github.com`。开始收尾时本地领先缓存的
   `origin/main` 六个提交，但没有 fetch，不能据此断言真实远端状态。恢复网络后先 `git fetch origin`、
   检查 `git log --left-right --oneline origin/main...main`，确认分支关系再正常 push，禁止强推掩盖分歧。
2. 设备：普通 SSH 先报系统 ssh 配置属主/权限错误；单次 `ssh -F /dev/null` 诊断仍被 socket 权限拒绝。
   没有更改系统配置或降低项目主机密钥校验。恢复可连接环境后先运行 baseline，再按维护说明迁移和验收。
3. 签名：临时 `gpg-agent` 直接启动也因绑定 socket 被拒绝；在正常主机补做严格 host CI。
   测试密钥不能作为发布身份，`packaging/release-policy.json` 仍未批准。
4. 恢复产物：firmware `0.20261107.2200` 和内核 chg3 原包仍缺；须连机确认文件后重打包并标记来源，
   不能将重新打包产物宣称为字节一致的原包。当前没有独立备份介质；同盘副本不能抵抗磁盘故障。
5. 功能：相机 MM0 阻塞、通话无声、稳定快充、GNSS 定位、传感器轴向、挂起续航及应用真实流程仍按 TASKS 验收。

在有网络权限的普通宿主终端，可使用恢复的信任密钥执行以下只读核对。
`-F /dev/null` 避开已发现的宿主 SSH 配置权限错误；保留严格主机校验，
若已知主机记录不匹配则停止。此命令不修复当前执行会话的沙箱权限：

```bash
cd /home/user/fuxi-linux/02-github-source
set -o pipefail
digest=$(sha256sum packaging/fuxi-device/root/usr/sbin/fuxi-kernel-install)
timeout -k 2s 40s ssh -F /dev/null -i work/ssh/id_ed25519 \
  -o IdentitiesOnly=yes -o UserKnownHostsFile=work/ssh/known_hosts \
  -o StrictHostKeyChecking=yes -o BatchMode=yes -o ConnectTimeout=5 \
  root@10.42.0.2 "python3 - --expected-installer-sha256 ${digest%% *}" \
  < scripts/fuxi-device-baseline.py | tee /tmp/fuxi-connected-baseline.json
```

核对器退出码 0 表示所查包/服务匹配，1 表示差异，2 表示证据不全；
SSH 连接失败通常返回 255。空输出不能当作验收报告。
取得实际报告后再准备支持包迁移、回退备份和启动验收。
