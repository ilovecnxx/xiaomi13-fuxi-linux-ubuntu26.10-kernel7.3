## ① /boot 标准化（BLS Type #1 + initramfs-tools）—— 调查结论（子 agent，只读）

**现在内建 initramfs** = `build/initramfs/{init,bin/busybox}` + `build/initramfs.list`（CONFIG_INITRAMFS_SOURCE，gzip），
构建入口 `fuxi-build-abl.sh`、`scripts/native-kernel-build.sh:85`、`scripts/fuxi-build.sh`。
`build/initramfs-root/init` 是废弃的旧版本（无引用）。显示 kick 已是 `fuxi-display-kick.service`，面板冷启动在驱动里，
USB gadget 是内建 g_cdc —— 都不依赖 initramfs。

init 功能去留（kexec 目标内核上）：
- proc/sys/devtmpfs、busybox → initramfs-tools 自带
- debugfs/tracefs、kmsg 标记、tty1 清屏、180 s 保险重启、900 s sysrq、ttyGS0 shell、主机窗口、杀 ttyGS0 持有者 → 去掉
  （shim 已提供主机窗口/串口；panic=10 + shim tries/fallback 兜底；调试用 `break=` 或可选 init-premount 脚本按 `fuxi.debug` 起 ttyGS0 shell）
- 挂 sda33 + switch_root → `root=PARTUUID=7f2e6802-83d9-47e7-9011-8bc643debd36 rootwait`，run-init /sbin/init
- fsck：现在没做（fstab passno 0）→ 根分区 passno 改 1
- 固件：保持根分区后的 `fuxi-firmware-devices.service`
- 模块：无（CONFIG_MODULES 关）→ `MODULES=list`
- NO_USB 报告：可选移到 `scripts/panic/fuxi-report`

**手机现状**：Ubuntu 26.10，systemd 261.3；initramfs-tools 未装（候选 0.151ubuntu3）；kernel-install 有
（插件 50-depmod/55-initrd/90-loaderentry/90-uki-copy，支持 devicetree，会从 /usr/lib/linux-image-<ver>/ 找 dtb）；
bootctl 无（不需要）。/etc/kernel/ 只有 postinst.d/postrm.d 的 zz-fuxi，没有 cmdline/install.conf。
sda33：PARTUUID 7f2e6802-83d9-47e7-9011-8bc643debd36，UUID 20261f81-56fa-4625-9461-55aada873732，LABEL fuxilinux-rootfs。
根需要的驱动全是 =y（UFS/PHY/RPMh/ICC/ext4），所以不带 initrd 也能 `root=PARTUUID=… rootwait rw` 起 —— 可作兜底。

**实施要点 / 坑**：
1. 手机：`apt install initramfs-tools`；`/etc/initramfs-tools/initramfs.conf`：MODULES=list、COMPRESS=zstd、BUSYBOX=y。
2. `/etc/kernel/cmdline`（取代 /etc/fuxi/cmdline）：去 `rdinit=/init`、去重复 `panic=0`，加 `root=PARTUUID=… rootwait`。
3. `/etc/kernel/install.conf`：`layout=bls`、`BOOT_ROOT=/boot` → 条目
   `/boot/loader/entries/<machine-id>-<ver>.conf`，linux/initrd/devicetree 路径相对 /boot（shim 要按 /newroot/boot 解析）。
4. deb 构建：CONFIG_INITRAMFS_SOURCE="" （fuxi-build-abl.sh 加开关）。
5. vmlinuz 是 Image.gz，静态 `kexec -c` 不收 → shim 解压到 tmpfs，或 install.d 插件在 90-loaderentry 后解压。
6. 钩子顺序：deb postinst → /etc/kernel/postinst.d（initramfs-tools 生成 initrd，再 zz-fuxi）→ zz-fuxi 调
   `kernel-install add <ver> /boot/vmlinuz-<ver> /boot/initrd.img-<ver>`；装完先看 /usr/lib/kernel/install.d 有没有重复插件。
7. 启动计数：先保留 shim 的 default/fallback/tries（/boot/fuxi/ 只剩状态文件），或改 BLS `+N-M` 文件名
   （systemd-bless-boot 只认 ESP/XBOOTLDR，fuxi-boot-ok.service 要自己改名）。
8. 过渡：shim 先同时支持旧 /boot/fuxi/<条目>/ 和 BLS，旧条目留作回退，确认后再删。

## ③ U-Boot 可行性 —— 调查结论（子 agent；U-Boot master feb8913 浅克隆在 ~/.cache/u-boot）

**结论：可行，第一阶段风险低。** 对 ABL 的打包方式不变（v1 镜像 + 厂商 DTB 诱饵，U-Boot 用自带 DTB，
board.c `board_fdt_blob_setup` 优先内建 DTB）。U-Boot 不碰 ADSP/基带/GIC ITS/GPI → kexec 的陷阱全部消失。

**以前 UEFI 为什么放弃**（docs/交接-给CODEX.md D.9–D.15、docs/参考项目与上游支持调研-fuxi.md §5）：
自制 edk2（FuxiLinuxBoot.c，无存储驱动）里 EFI stub 跑到 ExitBootServices 后 start_kernel 不运行，
根因未查清（怀疑手写 PE 加载/重定位）；GRUB 2.14 出菜单但没引导过内核；Mu-Silicium 被 ABL 拒或无 USB、无 UFS 驱动。
10-27 ABL 直接引导成功后用户选了它。

**U-Boot 上游现状（源码核实）**：用 `qcom_defconfig` + `board/qualcomm/qcom-phone.config`（不是 qcom_sm8550_defconfig，那个是 HDK uefi_a）。
有：CLK_QCOM_SM8550、pinctrl-sm8550（认 gpio-reserved-ranges）、ufs-qcom + sm8550 QMP UFS PHY、SPMI v7、RPMh、
pm8550 GPIO（音量+）、pmk8350 pwrkey/resin、simplefb（fuxi 的 /chosen/framebuffer 无 clocks，符合 phones.rst）、
EFI_LOADER/EFI_DT_FIXUP/BOOTMETH_EFILOADER/EXTLINUX、ext4 只读。
缺：QMP combo PHY(USB3) 无 sm8550、无 eUSB2 repeater → USB gadget 未必可用。dts/upstream 里没有 fuxi，用我们的 Linux DTB。
网上只见 Galaxy Z Fold5（q5q）SM8550 手机跑 U-Boot 的报告；无 Xiaomi/pmOS SM8550 先例。
线索：上游补丁 "sm8550: Fix DTBO boot failure"（2026-02，未合）称 ABL 叠 dtbo 需要基础 DTB 有 qcom_tzlog、arch_timer 标签 —— 可能就是我们 ABL 卡死的原因（推测）。

**必须关掉的危险默认**：EFI capsule（会写当前槽 **boot** 分区 = Android！）、UMS 菜单（把 LUN0 含 userdata 读写暴露给 PC）、
EFI_VARIABLE_FILE_STORE（往它以为的 ESP 写 ubootefi.var）→ `-d EFI_CAPSULE_ON_DISK -d EFI_RUNTIME_UPDATE_CAPSULE
-d EFI_CAPSULE_FIRMWARE_RAW -d CMD_USB_MASS_STORAGE -d EFI_VARIABLE_FILE_STORE -e EFI_VARIABLE_NO_STORE`，
env 的 preboot 置空、删 ums 菜单项。（主机缺 gnutls：另加 `-d TOOLS_MKEFICAPSULE -d TOOLS_LIBCRYPTO`。）

**存储/引导项**：没有 FAT ESP，GPT 禁写；sda33 是 ext4（U-Boot 只读）。现实选择：U-Boot extlinux
（/boot/extlinux/extlinux.conf）或从 ext4 加载 GRUB（grubenv 做启动计数）。systemd-boot 需要可写 ESP，暂不合适。
→ ① 的 BLS 条目格式仍然有用（GRUB 有 blscfg；extlinux 可由 fuxi-kernel-install 同步生成）。目标内核要关 FORCE_BUILTIN_DTB（deb 已经关）。

**首个实验 uboot0（只证明 ABL→U-Boot 能跑）**：
1. `make CROSS_COMPILE=aarch64-linux-gnu- O=<out> qcom_defconfig qcom-phone.config` + 上面的危险项关闭 + 改过的 env → `u-boot-nodtb.bin`
2. `cat u-boot-nodtb.bin <fuxi 日常 dtb> | gzip -9n` 再 `cat … build/edk2-msm/Platform/Xiaomi/sm8550/FdtBlob_compat/fuxi.dtb`，
   用 fuxi-build-abl.sh 同样的 mkbootimg 参数（v1、base 0、pagesize 4096、空 ramdisk）→ work/kbuild/abl-fuxi-uboot0.img
3. 只用 `scripts/fuxi-test-recovery.sh` 写；ssh 等待必然超时（正常）；回 Android：U-Boot 菜单 Reset 或长按电源 20 s；
   回滚：`scripts/fuxi-test-recovery.sh work/kbuild/abl-fuxi-shim7.img`。
4. 成功标准：屏上出 U-Boot 横幅/菜单，音量键/电源能操作。1b：`scsi scan; part list scsi 0; ls scsi 0:33 /boot`（只读）。
   2：load Image+dtb → `booti`（非 EFI 兜底），再试 `bootefi`。
子 agent 已干跑过构建（/tmp/ub-pkg/abl-fuxi-uboot0.img 1.38 MB，头有效），但那次没关 EFI 变量存储、用的原 env → **刷前必须重编**。
未验证：USB gadget、UFS 初始化、U-Boot 下 EFI stub、simplefb 与 GOP 双 framebuffer。
U-Boot UFS 初始化后 Linux 再初始化是否干净 —— 风险项。

## ③ 实测（11-07 深夜）：**U-Boot 链通了，可取代 kexec shim**
- uboot0 卡 MI logo：sm8550.dtsi 的 `memory@a0000000` 是大小 0 的占位，U-Boot 只读第一个 /memory → 构建时 `fdtput -r` 删掉。
- uboot1：simplefb 屏显 + 音量/电源键菜单 + UFS 只读（`scsi scan`、GPT 全表、`ls scsi 0:21 /boot`）。分区号十六进制（sda33 = 0:21）。
- uboot2：`booti` /boot/fuxi/7.4 deb2 的 Image + DTB → 桌面，5G/触摸/电池/声卡全正常，无 GPI/UFS 错误（shim 的约束⑦等全部不存在）。
- 手写 `/boot/extlinux/extlinux.conf` → `sysboot` 引导成功（cmdline 带 fuxi.uboot=ext）。
- `fuxi-kernel-install` 现在每次 add/remove/set-default 都重写 extlinux.conf（default 第一、fallback 第二、其余；`fuxi-kernel-install extlinux` 只重写）。
- **uboot3（57da97c5）= 现 recovery_b**：开机自动 sysboot extlinux（菜单 3 s，音量键选条目），按住音量下进 U-Boot 菜单，失败停在错误再进菜单。
  `adb reboot recovery` 到 ssh 可用 17 s（shim 链 60–80 s）；全功能实测。
- **自动回退（uboot4，b30bfcb3，用户 11-07 同意 U-Boot 受保护写盘）**：内存计数不行（内核 panic 后 ABL 进 Android，
  内存被 Android 覆盖），改学 GRUB grubenv：`/boot/fuxi/bootcount` 预分配 4 KiB，U-Boot 按块号原地改写数据块。
  保护：PARTUUID 对、ext4 读出 4096 字节、魔数 FXBC、块号在分区内、裸读块与文件逐字节相同；写后读回比较；pending=0 不写。
  流程：换默认条目 → `fuxi-bootcount arm`（pending=1）→ U-Boot 每次 tries+1 → `fuxi-boot-ok.service` 确认清零；
  tries≥2 → U-Boot 用 `/boot/extlinux/fallback.conf` → 回退条目起来后默认改成回退、记 default.failed。
  实测：arm→第 1 次启动确认 ✓；强制 tries=2 → 自动起 7.3 deb1 并改默认 ✓；set-default 7.4 → 计数 1 次后确认 ✓。
  ext4 条件：4 KiB 块 = UFS 逻辑块 4096、无 metadata_csum、data=ordered（文件数据不过日志）。
- fastboot（ABL）在本机 Intel 500 xHCI 上枚举 d00d 后掉线，重枚举 `error -71`（11-07 02:19）：主机侧 USB 信号/枚举问题，
  不是软件可修；试 USB 2.0 hub / A-to-C 线 / `usbcore.old_scheme_first=Y`。日常不需要 fastboot。
- 回滚：`scripts/fuxi-test-recovery.sh work/kbuild/abl-fuxi-shim7.img`。

- 钩子：`/etc/initramfs/post-update.d/zz-fuxi` → `fuxi-kernel-install initrd <版本>`：拷 initrd 进条目、重算 SHA256SUMS、
  重写 extlinux（条目带 `initrd` 行）、是默认条目就 `fuxi-bootcount arm`。所以 `update-initramfs -u` 也走计数保护。
- **root= 用 `UUID=20261f81-…`，不用 PARTUUID=**：Ubuntu `wait-for-root` 对 `PARTUUID=` 只在启动时设备已就绪才认得，
  设备晚到时 udev 事件只比 ID_FS_UUID/ID_FS_LABEL → 永远匹配不上，等满 30 s 超时（看起来像卡在开机字幕）。
  initrd 里 1.7 s 时 udev 还没处理完 sda33，所以每次都中。改 UUID= 后根挂载 32 s → 1.77 s，内核阶段 1.9 s，桌面 14 s。
- 自动回退在真实故障里验证过：诊断 initrd 写坏（PS4 里用命令替换 + debug → 无限递归）连续 2 次没确认 → U-Boot 自动起
  deb2、默认改 deb2、记 default.failed=deb3。教训：initramfs 里不要 set -x + 带 `$( )` 的 PS4。
- initrd 阶段固件加载失败（adsp/ipa/ath12k/a740_sqe）和 deb2 内建 initramfs 一样，正式系统里 fuxi-firmware-devices /
  fuxi-remoteproc 重试，不影响。
