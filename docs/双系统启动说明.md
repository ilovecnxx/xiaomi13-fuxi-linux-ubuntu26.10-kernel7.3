# 小米 13 双系统启动

当前路径：Android 原有启动链保持不变，Linux 使用 recovery_b 中的 U-Boot uboot7。
Linux 根文件系统是已有的 `/dev/sda33`（linux 分区）。本文不包含重分区步骤。

## 启动链

```text
正常开机 -> ABL -> Android 原有 boot 分区 -> Android
Recovery -> ABL -> recovery_b: U-Boot
                    -> extlinux -> Linux 内核 + DTB + initrd
                    -> /dev/sda33: Ubuntu
```

U-Boot 保持独立，日常更新 Linux 内核只安装 deb 包。首次安装或更换引导层才需要
部署 recovery_b；必须使用已核对镜像与备份，并遵循 README 中对应 Release 的说明。
内核 deb 和 fuxi-device 设备包须先就位，不得只替换引导镜像。

## 切换

- 从 Android 进入 Linux：`adb reboot recovery`，或 Android 高级重启菜单选 Recovery。
- 关机进入 Linux：按住音量上与电源键进入 Recovery。
- 从 Linux 再进入 Linux：`systemctl reboot --reboot-argument=recovery`。
- 返回 Android：在没有 recovery 启动请求残留时，执行不带 recovery 参数的正常系统重启。
  2026-11-12 实测 BCB `boot-recovery` 残留会让普通重启仍进入 Linux；最近一次进入 Linux 后再次残留，未清除。
  不要把一次重启或 USB 接口出现视为 Android 启动成功，须核对启动完成与 Launcher。
- 严禁 `reboot -f`、写 GPT 或切换槽位来做日常维护。

BCB 位于 `misc`，不属于日常 Linux 更新范围。历史清除仅获一次性授权，不可自动重复；
恢复前应核对当前内容、完整备份及哈希，明确具体写入范围。既有恢复证据见
[MM0 诊断与恢复](相机MM0诊断-20261112.md)，最新状态见 [TASKS.md](../TASKS.md)。

## 访问与检查

```bash
scripts/fuxi-ssh.sh
FUXI_HOST=<手机无线IP> scripts/fuxi-ssh.sh
FUXI_HOST=<手机无线IP> scripts/fuxi-health.sh
```

USB SSH 默认手机地址为 `10.42.0.2`，密钥和 known_hosts 保存在忽略的 `work/ssh/`。
电脑 USB 数据线和墙充的连接方式不同；使用墙充时可通过 WiFi SSH 检查。

## 更新与回退

构建、安装、启动计数和旧版本清理统一见
[`内核维护与独立升级`](内核维护与独立升级.md)。默认/回退条目由 fuxi-kernel-install
管理；连续两次启动未确认后 U-Boot 自动选择回退条目。不要手改 extlinux 配置。

起不来时保留当前 U-Boot，优先在菜单中选择已验证旧内核。长按电源可退出失败启动，
再按需要进入 Android 或 Recovery；不要反复覆盖 Android、固件或其他分区。

## 历史方案

ABL 直启、内建 DTB/initramfs 和 kexec shim 均已退出日常维护。
2026-10-29 原说明保存在 [`archive/双系统启动说明-20261029.md`](archive/双系统启动说明-20261029.md)。
shim7 镜像和旧脚本仅作应急存档；当前内核经兼容硬链接后的 shim7 启动尚未验证，
不能用它替代已验证的 U-Boot 多内核回退。
