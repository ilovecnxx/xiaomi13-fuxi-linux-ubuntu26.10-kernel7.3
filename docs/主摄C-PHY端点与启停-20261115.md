## 本轮实现

端点只在 SM8550 legacy PHY 开放 C-PHY，其他 SoC 或 generic PHY 路径返回不支持。
先读取原始属性，拒绝重复、越界、缺失或超过三个的 trio，避免通用 V4L2 parser
把重复配置静默替换为默认映射。保留 trio 顺序，范围为 0..2。只支持 ABC line order；
拒绝独立 clock lane、lane-polarities、clock-noncontinuous。端口必须位于 PHY 数量范围内。

新增实验属性 `qcom,cphy-settle-count`，含义是 400 MHz timer 下校准的硬件计数，
范围 1..65535，不是纳秒。与端点唯一的 `link-frequencies` 绑定；power-up 和
stream-on 都要求传感器明确提供的 link frequency 与该频率一致，不允许用同一个
settle 计数静默启动其他速率。多模式支持需另行设计和校准。这是隔离实验配方，
不代表此属性已获上游 ABI 接受。

C-PHY stream-on 在 D-PHY lane-mask/bpp 计算前分支，检查 timer 400 MHz、无 clock mux、
频率匹配后调用 PHY 2.1.2 后端；stream-off 调用该后端停机并返回其错误。
D-PHY 原路径仍使用原硬件操作及频率 fallback。SM8550 binding 的八个端口共用端点定义，
新增 C-PHY 示例，与原 D-PHY 示例一起校验。示例中的 1.5 GHz 是示意值，
**不是已确认的本机 IMX800 PLL 频率**。

同时修复 video 启动中途失败时未停掉已启动接收端的问题：保持原接收端到传感器顺序，
失败后遍历已成功启动的子设备并停流，保留原启动错误；未成功启动的实体不补调 stop。
真实 media graph 测试覆盖各阶段失败、清理后的重新启动、两轮正常启停和缺少可选回调。

## 停流错误限制

当前内核 `drivers/media/v4l2-core/v4l2-subdev.c:call_s_stream()` 会将驱动的停流错误
写入日志，再清除软件 streaming 状态并返回成功。本轮不改变公共 V4L2 框架。
因此 CAMSS 清理遍历能继续调用后续子设备，但不能据返回 0 证明硬件已停止或 DMA 安全。
真实硬件 halt/空闲确认与 MM0 重开故障仍须处理，主机清理测试不是修复完成证据。

最初两个失败测试错误地假定 V4L2 会传播 stop errno，并把返回 `-ENOIOCTLCMD` 的
回调当作缺少回调。现已改为验证真实 wrapper 的状态和日志行为、使用实际空操作表；
没有绕过框架或屏蔽告警。此前夹具未设置实体类型的提示也已消除。
