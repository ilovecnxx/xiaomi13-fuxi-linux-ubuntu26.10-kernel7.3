## 候选与验证

cam12order 将 CPAS 路径的共享时钟和启动握手移到带宽请求之前，传感器/DMA
仍在 runtime resume 成功后才开始。旧 DT 无 CPAS 路径的顺序保持不变。
带宽错误时先停止空闲 CPAS，再撤销已成功的请求并清理时钟引用，保留原错误。
清理握手失败另记错误；这不是实际 RPMh 超时后的恢复保证。

`edfabc4cd0cf8c50b5578e85db8487b9080e17e8`。配方见

需要单独的错误传播和失败状态验证，不能只改一个返回值后宣称恢复安全。
