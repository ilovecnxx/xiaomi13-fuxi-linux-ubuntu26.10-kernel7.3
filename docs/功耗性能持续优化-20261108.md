# 功耗、性能与自动化持续优化

目标：依据区间采样减少不必要的 CPU 活动，补齐可以自动执行的回归与诊断，逐项接入可验证的功能。
每项改动分别完成测试、设备检查、记录、提交与 main 同步；不能用构建成功替代硬件验收。

## 已完成：双卡消息监听改为事件驱动

`fuxi-qmi-sub2-msg.py` 原来以 50 ms 周期调用非阻塞 GLib iteration；没有短信或来电也会反复醒来。
现在使用 GLib MainLoop，由 QMI 文件描述符就绪分发事件，去掉人为的轮询间隔。
保留 30 秒绑定看门狗；失败返回非零供 systemd 重启，SIGTERM/SIGINT 和可选运行时限正常结束并释放 client。
短信 PDU 落盘成功后才应答的顺序保持不变。

设备运行 `7.4.0-rc1-fuxi-std2`，仅将 fuxi-modem 从 `0.20261108.5` 更新到 `0.20261108.7`，
并重启 `fuxi-sub2-msg.service`。ModemManager、81voltd 和桌面未重启。

两次读取监听进程主线程 `/proc/<pid>/status` 和进程 `/proc/<pid>/stat`，间隔约 20 秒：

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 采样秒数 | 20.003 | 20.002 |
| 主动上下文切换增量 | 385 | 2 |
| 非主动上下文切换增量 | 0 | 1 |
| 进程 CPU tick 增量（100 Hz） | 21 | 0 |

主动上下文切换约减少 99.5%；CPU 时间由 0.21 秒降到本次计数器采样精度以下。
这反映该服务的空闲调度开销，不是整机唤醒次数或电池续航提升比例。
手机通过 USB 充电，不能用此时电池电流计算断电续航；也未发送测试短信或拨打电话。

验证：

- 156 项主机回归通过，覆盖真实 GLib 事件分发与 SIGTERM、看门狗故障退出、时限退出与 source 清理、短信保存/应答顺序。
- 部署前后 deb SHA256 一致；绑定读回 `01`、VOICE/WMS 事件注册成功。
- 运行超过 30 秒看门狗周期后服务 PID 不变、`NRestarts=0`，未出现看门狗错误。
- 蜂窝状态 connected/home/attached，dpkg 审计无输出；`scripts/fuxi-health.sh --require-wifi --require-sensors` 失败项 0。
  包括实际经 WiFi 的 HTTPS、五类传感器读数、43 个有效热区和 3 个 CPU cooling 设备；Denial 无重试。
- 待现场验收：真实卡 2 短信接收与来电通知，以及基带实际重启后的恢复。

构建产物保存在 `work/apt-efficiency-20261108/`，不提交生成包或原始设备日志。
需要回退时，校验并安装 `work/apt-power-20261108/fuxi-modem_0.20261108.5_arm64.deb`，
只重启 `fuxi-sub2-msg.service`；不切换内核或重启桌面。

## 已完成：服务区间采样自动化

`scripts/fuxi-driver-audit.sh 40` 现在额外输出所选服务的 CPU 区间占用、主线程主动/非主动上下文切换增量及每秒速率。
通过 cgroup 精确识别双卡监听、基带 keeper、自动亮度和两个传感器服务，不读取进程参数、号码、短信或基带原始数据。
保留原有 `sensor_processes` 输出；新字段为 `service_processes` 和 `service_process_set_unchanged`。
PID/启动时间变化时不跨进程计算差值，进程集合变化单独标为 false；缺失/倒退的上下文计数保留 null。
集合未变化只表示两次快照身份一致，不保证所有预期服务都已运行，也不能排除窗口内短暂出现后退出的进程。

161 项主机回归通过。40.017 秒实机采样结果：

| 服务 | 单核 CPU 占用 | 主线程主动切换增量 |
|---|---:|---:|
| hexagonrpcd | 0.00% | 0 |
| iio-sensor-proxy | 0.00% | 0 |
| fuxi-modem-keeper | 0.25% | 23 |
| fuxi-auto-brightness | 0.07% | 40 |
| fuxi-sub2-msg | 0.00% | 2 |

采样期间进程集合不变，WiFi power save 开启，蓝牙 RX/TX vote 均 N。
全核 CPU busy 0.12% 是本次窗口状态；与之前窗口的屏幕/应用条件不完全相同，不能把全核差值全部归因于监听修改。
自动亮度仍有 1 秒检测周期；暂保留现有熄屏/手动滑块识别行为，后续按事件接口与实际收益评估。
设备包构建在 `work/apt-audit-20261108/`，仅安装 fuxi-device `0.20261108.8`，无需重启服务或系统。

## 已完成：兼容旧版 GLib 信号接口

GitHub Ubuntu 24.04 的 GLibUnix typelib 不提供新版 `signal_add`，导致前两笔提交的云端回归失败；
本地主机与设备使用较新 GLib，原测试未覆盖这一差异。双卡监听和自动亮度现在优先使用新接口，
不可用时回退 `GLib.unix_signal_add`。CI 显式安装 Python GI 和 GLib typelib，避免缺少依赖时跳过真实事件测试。

163 项主机回归和 61 项应用测试通过，覆盖新旧接口、真实事件分发、SIGTERM 和清理。
支持包构建在 `work/apt-glib-20261108/`；仅安装 modem/desktop `0.20261108.9`，
重启监听和自动亮度后均 active、`NRestarts=0`，WMS binding 读回 `01`。
ModemManager PID 733、Denial PID 865 保持不变，dpkg 审计无输出。
WiFi/传感器检查中五类读数、联网、温控均通过；唯一失败项为传感器进程路径带 `(deleted)`：
运行文件与磁盘文件 SHA256 均为 `dda3915c0244fb5fa305ce632806ddc3b4259d017d2324a2f8a6c778f96d12cd`，
是设备包升级替换 inode 后的检查误报，后续单独修正检查逻辑。最新云端结果以提交后的 Actions 为准。

## 推进顺序与边界

1. 继续使用服务 CPU/上下文切换区间采样评估优化，避免只比较进程生命周期累计百分比。
2. 排查其他常驻服务的空闲轮询，优先采用事件通知；保留连接恢复和手动控制行为。
3. 核查传感器、定位等能力的实际接口和依赖，能独立验证的逐项推进，未验收的保持明确标记。
4. 后续功耗对比需要固定亮度、网络、负载、电源条件和足够长的窗口；吞吐、交互延迟与挂起恢复分别验收。

继续暂停相机采集和快充实验。保留 std2/chg3、温控与当前桌面；不写 Android、GPT、固件、persist 或 EFS。
需要用户现场操作的明暗变化、耳机、来电、卫星定位等不标为自动验收完成。
