# 功耗、性能与自动化持续优化

目标：依据区间采样减少不必要的 CPU 活动，补齐可以自动执行的回归与诊断，逐项接入可验证的功能。
每项改动分别完成测试、设备检查、记录、提交与 main 同步；不能用构建成功替代硬件验收。

## 已完成：双卡消息监听改为事件驱动

保留 30 秒绑定看门狗；失败返回非零供 systemd 重启，SIGTERM/SIGINT 和可选运行时限正常结束并释放 client。
短信 PDU 落盘成功后才应答的顺序保持不变。

并重启 `fuxi-sub2-msg.service`。ModemManager、81voltd 和桌面未重启。

| 采样秒数 | 20.003 | 20.002 |

## 实验保留：CPU 请求上限与硬件读数

新增 `scripts/experiments/fuxi-cpu-profile.py`，默认不安装、不常驻、不在启动或电池事件中运行。
提供只读 `status`、`plan balanced|power-saver` 和显式 root `set`；其中 power-saver 只是实验配置名，
不是已验证的节能结论。工具只写 cpufreq 的 scaling_max_freq，不改 governor、最低频率、CPU 在线状态或温控。
计划先验证全部策略；限频档向下取频率表中不超过标称上限 70% 的档位，已有更严格上限不提高。
均衡档请求标称最大值，会解除其他工具设置的较低用户上限；不是恢复任意管理员自定义配置。
写入或读回失败时尝试逆序恢复本次快照，恢复失败单独报错；不保证断电或 SIGKILL 后自动恢复。
cpufreq QoS 通过内核工作队列异步更新，读回降低后的上限最多等待约 1 秒，避免立即读到旧值误报。
