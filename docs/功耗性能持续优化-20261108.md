# 功耗、性能与自动化持续优化

目标：依据区间采样减少不必要的 CPU 活动，补齐可以自动执行的回归与诊断，逐项接入可验证的功能。
每项改动分别完成测试、设备检查、记录、提交与 main 同步；不能用构建成功替代硬件验收。

## 已完成：双卡消息监听改为事件驱动

`fuxi-qmi-sub2-msg.py` 原来以 50 ms 周期调用非阻塞 GLib iteration；没有短信或来电也会反复醒来。
现在使用 GLib MainLoop，由 QMI 文件描述符就绪分发事件，去掉人为的轮询间隔。
保留 30 秒绑定看门狗；失败返回非零供 systemd 重启，SIGTERM/SIGINT 和可选运行时限正常结束并释放 client。
短信 PDU 落盘成功后才应答的顺序保持不变。

设备运行 `7.4.0-rc1-fuxi-std2`，仅将 fuxi-modem 从 `0.20261108.5` 更新到 `0.20261108.7`，
并重启 `fuxi-sub2-msg.service`。ModemManager、81voltd 和桌面未重启。

两次读取监听进程主线程 `/proc/<pid>/status` 和进程 `/proc/<pid>/stat`，间隔约 20 秒：

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 采样秒数 | 20.003 | 20.002 |
| 主动上下文切换增量 | 385 | 2 |
| 非主动上下文切换增量 | 0 | 1 |
| 进程 CPU tick 增量（100 Hz） | 21 | 0 |

主动上下文切换约减少 99.5%；CPU 时间由 0.21 秒降到本次计数器采样精度以下。
这反映该服务的空闲调度开销，不是整机唤醒次数或电池续航提升比例。
手机通过 USB 充电，不能用此时电池电流计算断电续航；也未发送测试短信或拨打电话。

- 部署前后 deb SHA256 一致；绑定读回 `01`、VOICE/WMS 事件注册成功。
- 运行超过 30 秒看门狗周期后服务 PID 不变、`NRestarts=0`，未出现看门狗错误。

  包括实际经 WiFi 的 HTTPS、五类传感器读数、43 个有效热区和 3 个 CPU cooling 设备；Denial 无重试。

## 推进顺序与边界

1. 将服务 CPU/上下文切换采样纳入可重复的自动诊断，避免只比较进程生命周期累计百分比。
2. 排查其他常驻服务的空闲轮询，优先采用事件通知；保留连接恢复和手动控制行为。
3. 核查传感器、定位等能力的实际接口和依赖，能独立验证的逐项推进，未验收的保持明确标记。
4. 后续功耗对比需要固定亮度、网络、负载、电源条件和足够长的窗口；吞吐、交互延迟与挂起恢复分别验收。

继续暂停相机采集和快充实验。保留 std2/chg3、温控与当前桌面；不写 Android、GPT、固件、persist 或 EFS。
需要用户现场操作的明暗变化、耳机、来电、卫星定位等不标为自动验收完成。
