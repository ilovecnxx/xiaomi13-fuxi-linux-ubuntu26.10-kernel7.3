# Phosh 自动亮度修复验收

2026-11-09，设备运行 `7.4.0-rc1-fuxi-std2` 与 Phosh。此前 `fuxi-auto-brightness.service` 通过 `BindsTo=denial.service` 绑定 Denial，而设备当前使用 Phosh，导致已有环境光传感器和亮度控制程序没有启动。

## 修复

- 自动亮度服务改为跟随 Phosh、Denial 和 Plasma Mobile 任一桌面会话；会话停止时由 `PartOf=` 停止服务。
- 三种会话的 systemd unit 均请求启动亮度服务，服务继续依赖 SensorProxy，并保留熄屏释放传感器、手动调节让出及有界亮度曲线。
- 包描述和服务日志改为通用桌面会话，不再误称只支持 Denial。

## 验收

- 新增 systemd 会话关系回归测试；`python3 -m unittest discover -s scripts/tests -v` 335 项通过，1 项环境依赖测试跳过；应用测试 61 项通过。
- `bash scripts/fuxi-ci.sh host` 通过。桌面候选包为 `fuxi-desktop 0.20261109.2101`，本地 SHA256：`505fd7316952ab257d0fa91aa3d05b79a9ca2adf542705fca866bb6598f16c50`。
- 通过 USB root SSH 安装到 Linux 根文件系统；设备回读包哈希一致，`dpkg-query` 显示版本 `0.20261109.2101`，`dpkg --audit` 无未完成状态。
- 设备上的 `systemd-analyze verify` 对 Phosh、Denial、Plasma Mobile 与自动亮度服务均通过。Phosh、SensorProxy 和自动亮度服务均为 active；亮度服务 `MainPID=10355`、`Result=success`。
- 屏幕保持关闭期间，8 秒前后亮度均为 `160/4095`、`bl_power=4`，服务没有写入亮度。journal 记录新通用会话服务成功启动。
- 未重启桌面或设备，也未切换会话。

## 尚未验收

设备屏幕在本次检查期间保持关闭，因此真实环境明暗变化、屏幕亮起后的亮度响应、Phosh 滑块手动接管及反复唤醒仍需现场验证。当前结果只证明 Phosh 下服务能够启动并遵守熄屏不写亮度的约束，不代表自动亮度完整验收或续航改善。
