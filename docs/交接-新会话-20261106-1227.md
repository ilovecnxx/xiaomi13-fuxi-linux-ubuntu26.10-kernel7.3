## 5. 已解决的问题
- 问题：写 role switch 没反应，dwc3 一直停在 device。
  - 根因：drd_work 卡在 `gserial_free_port`（`drivers/usb/gadget/function/u_serial.c:1255`）。它要等 ttyGS0 的所有打开者关闭，而 `fuxi-serial-shell.service`（ttyGS0 上的 shell/agetty）一直开着 ttyGS0。
  - 临时修法：停掉 fuxi-serial-shell，并杀掉占用 ttyGS0 的进程。之后切 host 立即生效。
  - 验证：xHCI 两条 root hub 都出现（上一会话实测）。
  - 永久修法还没做，见第 9 节。

## 6. 已尝试且失败的方案
- tracefs/ftrace 调试：这个内核没编 ftrace【已证实】。不要再试。
- 直接用 `ssh` 或 PATH 里的 `adb`：会被拒绝或找不到【已证实】。只能用 `scripts/fuxi-ssh.sh` 和 `tools/platform-tools/adb`。
- 停 fuxi-serial-shell 时 USB 上的 ssh 会断【已证实】。改走 WiFi 重连（10.10.10.43）即可。
- UCSI 绑定时插 U 盘：
  - 现象：typec partner 约 0.3 s attach、0.15 s detach，反复循环；dwc3 跟着在 host 和 device 之间来回切；xHCI add 日志超过 1400 行；dmesg 一次 `usb 1-1`/`usb 2-1` 连接都没有【已证实】。
  - power_role=source，opmode 1.5A，vconn_source=no。qcom-battmgr-usb 显示 online=0、电压 0，电池电流不变【已证实】。
  - 原因：推测 VBUS 没供出来。
- UCSI unbind 后强制 host，等 20 s：xHCI 稳定，但仍然没有任何设备连接，连 USB2 也没有【已证实】。单靠强制 host 不够，不要重复这个试验。

## 7. 仍存在的问题（严重度从高到低）
1. OTG 不识别设备【已证实】。根因【推测】，按可能性排：
   - a. VBUS/OTG 升压没打开。mainline 没有 vbus/otg regulator，VBUS 由 ADSP 经 pmic-glink 提供。原厂 `qti_battery_charger.ko` 有 `XM_PROP_VBUS_DISABLE`（XM 列表下标 6）、`XM_PROP_OTG_UI_SUPPORT`、`XM_PROP_CC_TOGGLE`、`XM_PROP_CC_SHORT_VBUS` 和 `typec_mode` 属性（证据：对 `work/modcheck/root/lib/modules/qti_battery_charger.ko` 跑 strings）。
     - 注意：这里的 strings 顺序只是字符串表顺序，和 TASKS 里记的原厂下标（AUTHENTIC=3、PD_VERIFED=24）对不上，不能直接当下标用。
     - 原厂 DT 的 pmic-glink/charger 节点里没有 otg/vbus 字样（grep `work/device-info/fuxi-live.dts`）。
   - b. eUSB2 repeater 缺 host 模式的调参。原厂 `fuxi-live.dts:14290-14298` 有 `qcom,param-override-seq` / `-host` / `-host-ms` 三组参数，格式是 (值, 寄存器) 对。mainline `phy-qcom-eusb2-repeater.c` 只读一组 `qcom,tune-*`，`set_mode` 里 host 和 device 只切 FORCE_EN_5/VAL_5 时钟。mainline 的 `&pm8550b_eusb2_repeater`（`sm8550-xiaomi-fuxi-min.dts:648`）只写了供电，没有调参。
2. 和电脑之间 USB 数据链路不通，休眠后识别测不了【已证实没通】。根因未查，可能和第 1 条有关【推测】。
3. ttyGS0 阻塞 role switch 只是临时绕过，重启后又会出现【已证实】。
4. DP 显示没实测（没有显示器）。
