# 驱动初始化与功耗验收

## 范围

设备为 Xiaomi 13（fuxi），内核保持 `7.4.0-rc1-fuxi-std2`，默认 std2、回退 chg3。
本轮没有修改内核源码、配置或固件，优化集中在外设初始化依赖、错误检测和可重复的只读测量。
相机和快充实验继续暂停，没有运行相机采集，也没有写 Android、引导或固件分区。

原 `fuxi-firmware-devices` 串行执行 ADSP/IPA、WiFi 和蓝牙恢复，蓝牙重绑还需等待 1 秒。
现将 ADSP/IPA 保留在原服务，新增 `fuxi-wifi-init` 和 `fuxi-bt-init` 并行执行，
分别约束 NetworkManager/管制域服务与 bluetooth/地址服务；传感器不再等待无线外设恢复。
MPSS 仍由 rmtfs 启动；已绑定的 ath12k 禁止重绑。蓝牙保留已验证的一次启动重绑行为。
缺少固件或绑定失败现在会返回失败，启动健康确认也要求三个初始化服务全部 active。
安装包升级只启用新服务，不立即重绑正在使用的无线设备。

## 启动实测

`0.20261108.2` 与 `0.20261108.3` 各一次启动，以下为 systemd
`ActiveEnterTimestampMonotonic` 换算的启动后秒数，不是桌面整体开机耗时，也不是多轮统计。

| 服务就绪 | 优化前 / 秒 | 优化后 / 秒 |
|---|---:|---:|
| ADSP/IPA 初始化完成 | 5.420 | 3.316 |
| hexagonrpcd active | 5.460 | 3.604 |
| SensorProxy active | 6.681 | 4.849 |
| WiFi 管制域设置完成 | 6.552 | 5.666 |
| bluetooth active | 7.743 | 6.198 |
| 蓝牙地址设置完成 | 7.760 | 6.200 |

重启后 `scripts/fuxi-health.sh --require-wifi --require-sensors` 失败项为 0；
WiFi HTTPS、管制域、蓝牙上电及加速度、光线、距离、磁场、指南针采样通过。
启动确认 pending=0、tries=0、once=0，未观察到新 RPMh/UFS/ADSP 故障或 D 状态线程。
initramfs 缺固件引起的早期 ath12k/蓝牙探测失败仍存在，本轮改善的是根文件系统就绪后的恢复顺序。

## CPU 与无线检查

- 三个 CPU 策略均使用 schedutil，cpuidle 已启用；保留现有频率、温控和节能配置。
- 8 个进程各固定一个 CPU，执行 SHA-256 运算 8 秒；每秒采样频率、温区与 cpufreq cooling state，设 80°C 停止条件。
  三个策略观测频率为 2.016、2.8032、2.9568 GHz；温区最高值从 48.3°C 到 59.0°C，cooling state 均为 0，8 个进程正常退出。
  这是短时调频检查，不能证明持续性能或温控限频效果；首次测试因 Python 3.14 默认 forkserver 无法导入 stdin 失败，指定 fork 后重测通过。
- WiFi 节能开/关各做 20 包网关 ping，均无丢包，平均延迟分别 4.652/4.798 ms；保持节能开启。
  该短测不能证明吞吐、漫游或长期延迟表现。
- 空闲基线 10 秒全 CPU 平均忙碌比例为 0.06%，两个传感器进程为 0.0%；蓝牙 IBS 的 rx_vote/tx_vote 均为 N。
  这些是软件计数器，不能代替电流表或电池续航测试。
- 负载结束并安装最终包后的 10 秒采样：全 CPU 平均忙碌比例 0.43%，两个传感器进程仍为 0.0%，
  WiFi 节能开启，蓝牙 rx_vote/tx_vote 为 N；cpuidle 保持启用，无 D 状态线程。
  两次空闲窗口条件不同，不据此推断功耗改善或回退。

## 测量入口

```bash
scripts/fuxi-driver-audit.sh 10
scripts/fuxi-health.sh --require-wifi --require-sensors
python3 -m unittest discover -s scripts/tests -v
```

区间采样默认 10 秒，接受 1–60 秒，输出 JSON 到 `work/driver-audit/`；
也可在设备上运行 `/usr/libexec/fuxi/fuxi-driver-audit --seconds 10`。
内容包括调频策略、温区、cpuidle 计数器差值、WiFi 节能、蓝牙 IBS 和传感器进程 CPU 时间，不收集 SSID、MAC 或口令。
`cpu_busy_percent_all_cores` 为所有 CPU 时间的平均忙碌比例；进程 `cpu_percent_one_core` 以单核为 100%。
cpuidle 时间通常在退出空闲时记账，短窗口存在边界偏差，不能把其值当作精确耗电比例。

## 打包、验证与回退

134 项主机回归通过，包括固件缺失/绑定失败、不同初始化模式隔离、禁止重绑已绑定 WiFi、
进程 PID 复用与 CPU 单位，以及初始化服务失败时拒绝启动确认。
未修改内核，无需新增内核子系统 W=1 编译；不以设备包构建替代实机验收。

最终设备包为 `fuxi-device_0.20261108.4_arm64.deb`，SHA-256：

```text
11ec73cd5a2d53b14f4a17da359113b94359758d4fca36c045bb2dccc4c42489
```

使用 `FUXI_APT_LOCAL=1 FUXI_APT_SUPPORT_ONLY=1` 和标准 `scripts/fuxi-build-pkgs.sh` 构建；
仅安装 device 包。`.3` 完成重启验收，`.4` 追加新初始化服务的启动健康门槛，安装后手动健康检查、
systemd 单元校验和 dpkg 审计通过，不为这项检查再次重启。
最终包安装后首次完整健康检查有一项失败：正在运行的传感器 daemon 旧 inode 被替换，
`/proc/PID/exe` 路径带 `(deleted)`，与健康检查的期望路径不符；当时五类采样均正常。
通过仅重启 hexagonrpcd 并启动 SensorProxy 处理，未重启桌面或重绑无线设备。
处理后最终完整健康检查失败项为 0，日志为 `work/claude-logs/health-20261108-023913.log`；
当时 43 个有效温区最高读数 37°C，五类传感器采样、WiFi HTTPS 和蓝牙上电均通过。
原始启动、采样、负载和回归日志保留在 `work/driver-audit/`，不提交设备原始日志。

回退设备包可用已核对的 `/var/tmp/fuxi-device_0.20261108.2_arm64.deb`。
先用 `systemctl disable fuxi-wifi-init.service fuxi-bt-init.service` 清理新增单元的启用链接（不加 `--now`），
再安装旧包，按项目流程重启 Linux。回退 device 包不改变独立内核条目；该降级流程本轮未实机执行。

## 仍需独立验收

- 持续 CPU 性能、真实电流/续航、WiFi 吞吐和长时间连接稳定性。
- 挂起/恢复、蓝牙耳机 A2DP；当前空闲自动挂起仍关闭。
- SensorProxy 固件 mount matrix 为零后的 identity 回退警告：物理方向和标定尚未核实。
- 将固件纳入 initramfs 或模块化驱动以消除早期探测失败，需要单独评估启动体积与回退路径。
- 相机互连阻塞、通话无声和小米快充握手仍是原有未完成事项。
