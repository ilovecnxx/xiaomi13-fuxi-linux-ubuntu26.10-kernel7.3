# 驱动初始化与功耗验收

## 范围

早期初始化验收设备为 Xiaomi 13（fuxi），内核保持 `7.4.0-rc1-fuxi-std2`，默认 std2、回退 chg3。
本轮没有修改内核源码、配置或固件，优化集中在外设初始化依赖、错误检测和可重复的只读测量。
相机和快充实验继续暂停，没有运行相机采集，也没有写 Android、引导或固件分区。

原 `fuxi-firmware-devices` 串行执行 ADSP/IPA、WiFi 和蓝牙恢复，蓝牙重绑还需等待 1 秒。
现将 ADSP/IPA 保留在原服务，新增 `fuxi-wifi-init` 和 `fuxi-bt-init` 并行执行，
分别约束 NetworkManager/管制域服务与 bluetooth/地址服务；传感器不再等待无线外设恢复。
MPSS 仍由 rmtfs 启动；已绑定的 ath12k 禁止重绑。蓝牙保留已验证的一次启动重绑行为。
缺少固件或绑定失败现在会返回失败，启动健康确认也要求三个初始化服务全部 active。
安装包升级只启用新服务，不立即重绑正在使用的无线设备。

2026-11-17 保持相同 suspend5 内核与 DTB，仅给采集工具增加显式 `--glink-metadata`。
该选项要求现有 13 个 glink 命令 tracepoint 全部可用，否则在设置 RTC 前拒绝并清理。
先记录 5 秒基线，再设置 20 秒 RTC；记录通道、方向、命令、长度和 intent 等协议元数据，
不读取消息载荷。默认不启用该选项。源码核对表明 RX trace 在 rpmsg 客户端回调之前，
TX trace 在发送函数调用之前，因此 TX 事件不能单独证明发送成功。

20 秒 RTC 定时唤醒和整机深睡仍未通过。USB HS-PHY L2 与 PCIe LTSSM 0x12 提示仍在。

trace 按行顺序关联到以下通信：

- 5 秒基线没有 LPASS 数据，只有 MPSS 数据。挂起请求后、进程冻结前，qmi-proxy 向
  LPASS `IPCRTR[1/3]` 发送多条 52 字节消息并收到 rx_done；这只是缓冲区传输确认，
  不是 RPC 业务回复，intent ID 也不是 RPC transaction ID。
- 整个进入前捕获窗口没有 `PMIC_RTR_ADSP_APPS` 的 TX/RX。syscore_resume 于
  1052.070037 结束，随后 IRQ13→IRQ230；在同一父 IRQ 内，1052.070096 和
  1052.070132 首先收到 `PMIC_RTR_ADSP_APPS[4/8]` 两条各 220 字节消息，intent 2/3、
  left_size=0。缓冲区确认在 1052.071194/1052.071211 发出。
- 该 PMIC 通道的主机 TX 24 字节在 1053.281208，随后 RX 24 字节在 1053.281877；
  fastrpc TX 40 字节更晚。不能把这些恢复后的请求当成进入前未完成请求。

这把 LPASS pending 与 PMIC 通道数据关联起来，尚不能证明最早唤醒原因。
`pmic_glink_rpmsg_callback()` 根据 header.owner 分发，通道由电池、USB-C/altmode 等
客户端共享，220 字节不能确定 owner/type/opcode。battmgr 现有 `diag` 读取会主动发送
GET 请求，本轮没有使用该入口作为被动统计。下一步需设计仅 PMIC header 元数据及 TX
结果的追踪，经源码和编译验证后再进行新实验，不采集载荷、不停止充电。
