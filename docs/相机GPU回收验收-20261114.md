# GPU 软件 ISP 资源与错误回收验收

日期：2026-11-14。目标是修复可复现的 EGL image 泄漏及错误帧丢失，不把
短时成功采集认定为历史 GPU 停帧、MM0 或全部相机功能已解决。

## 环境与候选

- 实机运行 `7.4.0-rc1-fuxi-cam6hfclk`，测试前启动已确认；下次默认预设 deb9，回退 deb8。
- OV13B10；普通 `fuxi` 用户，`LIBCAMERA_SOFTISP_MODE=gpu`，内存扰动 191。
- libcamera v0.7.0 固定 commit `b7854fd07d42168f099b5ce30d1702e0e0875bf5`。
- 对照版仅包含首帧初始化补丁；候选叠加 GPU 回收补丁，详见
  [固定配方](../packaging/experiments/libcamera-gpu-lifecycle/README.md)。
- 两版都在手机原生构建目录运行，不替换系统库，不改变标准内核配方。

## 缺陷与对照

`DebayerEGL::debayerGPU()` 每帧导入输出 DMA-BUF，新 EGL image 覆盖旧句柄，
却没有逐帧销毁。导入返回值未检查；绘制或映射失败后只标记 FrameError，
未归还输入/输出缓冲。即使补上归还，simple 管线仍会等待未产生的 IPA 元数据。

补丁给图像句柄设空初值、检查导入结果、用作用域退出清理在 GPU 完成后释放
本帧 image，并在失败时清零 bytesused、结束 DMA 同步、归还缓冲及取消元数据等待。
FBO 错误路径同时清空已销毁句柄。

使用仅针对 cam 的 LD_PRELOAD 审计库，通过真实 EGL 扩展调用计数：

| 对照 | 结果 |
|---|---|
| 仅首帧补丁，30 帧 | 创建 30、销毁 0、退出前未销毁 30、存活峰值 30 |
| GPU 补丁，120 帧 | 创建 120、销毁 120、未销毁 0、存活峰值 1 |

此前仅首帧补丁的半尺寸/全尺寸各 900 帧也正常退出，证明“出帧成功”本身
不能检出此泄漏，也不能据此把历史停帧归因于它。

## 故障注入

导入失败、FBO 不完整、绘制错误三类，各测第 5 次调用单次失败和连续失败，
每个进程要求完成 60 个请求。六项都已通过：单次失败返回 1 个空错误缓冲后
继续采集，连续失败返回 60 个空错误缓冲并正常退出，没有缓冲耗尽后停住。
创建与销毁配对，未销毁计数 0，无重复销毁；连续导入失败从未创建 image，
其存活峰值为 0，其他项为 1。

原版反例连续注入绘制错误后没有完成请求；8 秒 SIGINT 超时及随后 3 秒宽限
仍未正常退出，timeout 最终以 SIGKILL 结束进程，退出码 137。结束后没有残留
cam 或 D 状态任务，CAMSS suspended、HF enable count 为 0。此结果作为预期
失败反例记录，不计作验收通过；补丁版同类 60 个错误请求正常退出。

注入发生在实际导入或绘制调用边界；不能代表真实驱动损坏、GPU hang、
CPU mmap 失败、内核 D 状态或系统挂起。cam 输出只含 bytesused，FrameError
状态来自补丁实现，未另用 API 客户端断言。日志不含照片。

## 验证范围

- GPU 正常采集：三轮半尺寸/全尺寸各 900 帧，加全尺寸 3,600 帧，共 9,000 帧，
  全部正常退出、没有空错误缓冲、image 创建/销毁配对。加六个故障进程，矩阵
  共完成 9,360 个请求。各进程结束后 CAMSS suspended、HF 门控 enable count 为 0，
  未见 RPMh batch/AMC、blocked、EXT4 或 I/O 故障标记。
- 同一 GPU 补丁构建强制 CPU 路径：半尺寸 300 帧、全尺寸 120 帧均通过。
- 半尺寸与全尺寸是脚本的请求尺寸 2104x1560、4208x3120；配置可由 libcamera
  调整，不能把请求尺寸直接当成逐像素画质验收。
- 原生编译成功；上游测试 45 通过、1 预期失败、29 跳过、0 失败。
- 源码归档和两个补丁哈希、正向应用、逆序回退检查通过。
- 手机实际六个修改文件 SHA256 与配方重放结果逐一一致，系统 libcamera /
  libcamera-base SHA256 与本轮开始前相同。
- ShellCheck 通过。主机检查器包含漏帧、乱序、泄漏、重复销毁、意外错误、
  缺失/重复审计报告等回归用例；严格主机回归 354 项脚本测试和 62 项应用测试通过。
- 本次没有内核改动，不以本测试替代 W=1 内核构建或其他传感器验证。

## 恢复状态

测试结束核验 deb9/deb8 启动文件后，通过普通 recovery 重启回到
`7.4.0-rc1-fuxi-deb9`。运行/默认 deb9、回退 deb8，启动计数
`pending=0 tries=0 once=0`，Phosh active。要求无线/传感器的健康检查失败项为 0；
传感器矩阵回退、轴向和单位等原有警告仍保留。没有清除 BCB、重启桌面或
安装实验相机库。保留手机原生构建和忽略的实测日志，供后续开发复用。
