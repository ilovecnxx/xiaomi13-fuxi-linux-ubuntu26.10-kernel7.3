### 2026-11-09 LineageOS 交叉对照

设备运行的是 LineageOS 24.0（`24.0-20261102-NIGHTLY-fuxi`，Android 17），不是 MIUI。无线 ADB 读取 `dumpsys sensorservice` 的 BMI26x 加速度计最近事件环形缓冲区，50 条样本时间为 18:24:26.387–18:24:34.762，XYZ 范围分别为 X `-0.16…-0.15`、Y `+0.12…+0.14`、Z `+9.81…+9.83 m/s²`。这是 Android Sensor HAL 历史样本，不是 18:29 读取时的实时流；事件缓冲区显示 Android 暴露的加速度计 X 接近零，与 Linux 隔离候选库在屏幕朝上时 X 约 `-0.05 m/s²` 相符，也与 Linux 原系统库约 `+0.93 m/s²` 不符。

该设备 fingerprint 标示原厂版本 `OS3.0.307.0.WMCCNXM`；本地 `work/stock/fuxi_images_OS3.0.309.0.WMCCNXM_16.0/` 是 OS3.0.309 原厂包，不能把其版本当作设备当前运行系统，也不能用本次 LineageOS 读数声称 MIUI 实测。当前结果支持 Linux `libssc` 矩阵处理造成额外 X 分量的判断，但两套 Android/Linux 传感器栈并非同一算法实现。没有安装候选库或改动设备配置。

后续通过 USB ADB 与 Magisk root 只读核对到，LineageOS 设备的 vendor fingerprint 仍标示 `OS3.0.307.0.WMCCNXM`。`/odm/etc/sensors/config/sm8550_bmi26x_0.json` 的 SHA-256 为 `b547506f662e1cca60025094f40fe77b67324e60f7be85a6c27fb69da5912e92`；其 `.placement` 共 12 项，索引 0–2 为 `0.1`，索引 3–11 为 `0.0`。这确认当前 Android ODM 静态配置也保留该组数值，但配置字段布局不等于已确认的运行时矩阵语义；本次未读取或更改 persist 注册表，也未更改手机。

## 数据通路

ADSP sensorspd → SSC QMI/QRTR 400 → libssc → iio-sensor-proxy → Phosh/桌面。
`hexagonrpcd` 经 FastRPC 为 ADSP 提供只读文件服务，文件是本机 Android 的副本。

原始副本根目录为 `/var/lib/droid-juicer/sensors`：

| 路径 | Android 来源 |
|---|---|
| `acdb/` | `/vendor/etc/acdbdata` |
| `dsp/` | `/vendor/dsp` |
| `sensors/config/` | `/vendor/etc/sensors/config`（1 个） |
| `sensors/odm-config/` | `/odm/etc/sensors/config`（56 个） |
| `sensors/registry/` | `/mnt/vendor/persist/sensors/registry/registry`（311 个） |
| `sensors/sns_reg.conf` | `/vendor/etc/sensors/sns_reg_config` |
| `sensors/sns_reg_version` | `/mnt/vendor/persist/sensors/registry/sns_reg_version` |
| `socinfo/` | `/sys/devices/soc0` 六项设备信息 |

`adb pull -a` 和 `tar -xf` 保留 mtime；Linux 副本使用 root:fastrpc、目录 0750、文件 0640。
真实 persist 不被写入。日常 daemon 使用 `/var/lib/fuxi-sensors-prebuilt`：
引用现有 registry、版本、socinfo、dsp/acdb，配置目录保持为空，复用 Android 已生成的标定注册表。
这是当前实测可用的启动方式；完整配置目录仍保留在原始副本中。

## 脚本

```bash
scripts/fuxi-build-hexagonrpc.sh         # 本机编译与文件映射测试，不访问手机
scripts/fuxi-sensors.sh --deploy-only   # 已在 Linux：部署已采集的本机文件，重启传感器服务
scripts/fuxi-sensors-proxy.sh           # 部署桌面规则和有界就绪检测，复用支持 SSC 的现有包
scripts/fuxi-health.sh --require-sensors # 只读检查五类数据、桌面接口、启动状态
```

不带 `--deploy-only` 的 `fuxi-sensors.sh [镜像]` 会先回 Android 采集文件，
然后沿原测试流程写入 recovery_b 并返回 Linux；默认镜像为 daily-pm1。
`fuxi-sensors-proxy.sh --rebuild` 才会强制重编已支持 SSC 的包；构建目录和日志保留。
