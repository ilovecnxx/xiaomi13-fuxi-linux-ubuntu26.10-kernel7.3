# 主摄 C-PHY 频率与时钟

本轮只推进 IMX800 主摄，以最新通过主机验证的 `cphy-phy` 继续开发。
Linux 已恢复；本轮没有部署、重启或采集，不改变最近核实的运行/默认 cam12order、
恢复入口 deb9。其他摄像头延期，持续验收仍以[基础相机目标](基础相机目标.md)为准。

## 本轮通过的源码

- 候选 `cphy-clock`：`3038e196d0839a19ba05f9f354115ef297d0bad4`。
- tree：`8e55bd9348e4c6c9adf60cb5603044ebf6d80e8a`。
- 父源码：`cd664341a4bf475c5e9a52665ba254b039c0cb13`，保留共享修复、接收端配置和 PHY 后端。
- C-PHY 读取传感器明确提供的 `get_mbus_config.link_freq` 或 `V4L2_CID_LINK_FREQ`；
  缺失或错误向调用者返回，不再允许套用 D-PHY pixel-rate fallback。D-PHY 原有 fallback 保留。
- V4L2 C-PHY link frequency 按 `ceil(link_freq * 32 / 7)` 换算每 trio 的 bits/s；
  先检查 PHY 表上限再乘法，覆盖超过 32 位的输入及溢出风险。
- SM8550 RX 按厂商 `floor(data_rate / 32) + 1` 选择严格更高的档位；timer 独立固定
  400 MHz。设置前检查可用档位，设置后检查 CCF 返回的实际速率，防止 provider
  设置失败被 CCF 吞掉后继续。错误发生时原 power-on 调用者释放 regulator 和 PM 引用，
  不进入 PHY clock-enable。关闭状态下可能保留已写的 clock rate，不能据此判定 enable 泄漏。
- CSID 对 C-PHY 的传感器频率错误也向上传递。SM8550 CSID 资源使用固定档位，
  本轮不改变 CSID 时钟公式或公共 CCF。
- 端点仍拒绝 C-PHY，PHY stream-on/off 尚未集成；没有 IMX800 驱动或主摄帧。

## 厂商字段转换证据

公开参考仓库 `comprehensive9/vendor_qcom_proprietary` 固定提交
`36fc163a534963a5b3af52186af5efcc63401ad2`：

| 文件 | 核实内容 | SHA256 |
| --- | --- | --- |
| `camx/src/core/camximagesensordata.cpp`，`CreateCSIPHYConfig()`，2834 行起 | settle 字段乘 200000000；dataRate 为经 override 后的 outputPixelClock × bitWidth / laneCount | `02bb5575cba91cc75f82505820ac35bf03e479192d3aa37140988d1b8957fc48` |
| `camx/src/settings/common/camxsettings.xml`，2094 行起 | `overrideOPPCLOCK` 是百分比，公共默认 0，可由 `persist.vendor.camera.overrideOPPCLOCK` 改变 | `402c0cb2f26966235d20a7ce7a9c538cdfdb53f81442200020ee4d7697378ae7` |

MiCode `camera-kernel` 固定提交 `6c6099a85cb3154fc8a744c17b6b9f5fd361dea8`
的 `cam_csiphy_core.c` 再把 settle 除以 200000000。因此这条公开代码路径中，模块
`settleTimeNs=30` 最终是硬件计数 30，不能按字段名称直接解读为 30 纳秒。
这是上层转换证据，尚未证明本机当前厂商二进制或所有模式都采用相同实现。

模式 1 的 semco 模块候选为 4096×3072 RAW10、三个 trio、outputPixelClock=1988020000。
假定 override=0，厂商带宽投票为 `1988020000 * 10 / 3 = 6626733333` bits/s/trio，
落入上限 6840000000 的 3.0 Gsps 档。仅作换算测试时可用 link frequency=1449597917 Hz，
反算向上取整为 6626733335 bits/s，档位不变。**此测试值不是已验证的传感器 PLL 频率**，
不能直接作为 IMX800 驱动常量；实际 PLL、模块装配、trio 接线和 override 仍须核实。

V4L2 公式依据当前内核 `Documentation/driver-api/media/tx-rx.rst`：
`pixel_rate = link_freq * 2 * lanes * 16 / k / bpp`，C-PHY 的 k=7。
PHY 后端保留厂商使用 2.28 bits/symbol 取整后的带宽阈值，不混用阈值档名与 link frequency。

原厂本机 DTB `work/device-info/fuxi-live.dtb` 的 `/soc/qcom,csiphy2@ace8000`：
clock-names 为 `cphy_rx_clk_src csiphy2_clk csi2phytimer_clk_src csi2phytimer_clk`，
两个档位 lowsvs/nominal 对应 `400000000 0 400000000 0` 和
`480000000 0 400000000 0`，src-clock-name 为 `csi2phytimer_clk_src`。
与现有 SM8550 CAMSS 的 RX 400/480 MHz、timer 400 MHz 资源表一致。
DTB SHA256 为 `616602d1b5300214fa51a3a9c2f248c57265f6f7aca2d9ef90d54540275c32e1`。
